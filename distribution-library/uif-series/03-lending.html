Lending — DSCR Math Is Easy. Trusting the Inputs Is the Product.

For: brokers and loan officers originating DSCR loans for real estate investors Alt headline: The Rent Roll Your AI Misread Keyword: DSCR loan document automation

The ratio itself is one line: qualifying monthly rent divided by monthly PITIA.

Nobody loses a deal on the division. They lose it on the inputs. A borrower sends 11 leases, a rent roll, and a tax bill as phone scans. An AI tool pulls the numbers and drafts the file. One lease says $1,450; the rent roll says $1,540, and the tool takes the bigger one. A vacant unit gets counted. An annual tax figure lands in a monthly field. The ratio clears 1.25 on your desk and fails in underwriting. Now you're re-papering a deal the investor thought was done.

The fields that broke: Rent, taxes, insurance, and association dues — every input to the ratio. Each wrong value looked like a real one.

The missing pins: The fuse and the output line. The model was extracting values and doing the math, so nothing stood between a misread number and the final ratio.

The fix: The model extracts; it never calculates. Code computes the ratio from the extracted values. Every value carries its page and line: lease 7, page 2, paragraph 4. Conflicts between documents block the file and print side by side, so a person picks the right one. Which rent figure qualifies is set by the lender's guidelines, configured once, not decided by the model each time. The result is a borrower package where every number points to the paper it came from. Underwriting gets fewer surprises; you get fewer re-papers.

Where else this shows up: Splitting reading from math is one of the most portable moves on the board. A lien deadline is the same problem with dates instead of dollars (Construction). Detention pay on a rate con is the same problem with timestamps (Freight). Wherever a model both reads and computes, separate the jobs and let code do the arithmetic.
