2. Memory loop simulator

One turn runs five steps in order: PROMPT (write or load a 5-block prompt) -> WRITE GATE (the eight memory-gate questions, illustrative thresholds) -> MEMORY STORE (session only, in-page) -> RECALL (the stored prompt is retrieved on the next turn) -> REFINE (edit the recalled prompt and run again). Each step shows its input, its decision, and its output.

Write-gate thresholds are ILLUSTRATIVE. The JGI paper gives no numeric thresholds. This demo reuses the memory-gate demo rule with the same label: evidence below 3 REJECTS, a contradiction QUARANTINES even at high evidence, evidence below 6 QUARANTINES, otherwise WRITE. Never read these numbers as paper rules.

Each library prompt is built in the registry-stated 5-block shape (Identity, Context, History, Rules, Handoff). The Context block carries one content-bank fact verbatim, cited. The other four blocks are assembled for this demo and labeled as such on the page and in the code. No library prompt is quoted from a PMLA paper or repo; none was found in the sources read.

6. Design decisions (mine, labeled as mine)

No source defines a runnable PMLA loop, a prompt library, a session store, or a turns-to-days mapping. Everything in this section is my design, not a paper or registry claim.

  • Five steps, in this order: PROMPT, WRITE GATE, MEMORY STORE, RECALL, REFINE. The order applies the stated loop idea (prompt as memory) to the stated write gate. RECALL reads the store at the start of a turn; REFINE is the user editing the recalled prompt and running again.
  • Store rule: only WRITE verdicts store. REJECT and QUARANTINE record a receipt for the decision but store nothing. The store keeps every written prompt as history; the latest written prompt is the current one. Supersede keeps the old record as history, never deletes it.
  • 5-block parsing: blocks are ## Name headings, matched case-insensitively. A prompt with no headings parses to five empty blocks and is reported as unstructured; it can still run the gate, because the gate judges the write, not the block shape.
  • Library prompts: facts verbatim from the content bank with the item cited; the other four blocks assembled for this demo. Library prompts are teaching examples, not quoted PMLA source text.
  • Recall freshness mapping: 1 loop turn = 1 day of age, computed at the lead preset (h = 7 days). Chosen because the loop has no clock; the mapping is displayed next to every recall so it is never mistaken for a source rule.
  • Receipts: one per turn, including REJECT and QUARANTINE turns, so the trace is a complete record of decisions, not only of writes. Sealed with the verbatim pure-JS SHA-256 from the governance-loop demo; verified per receipt with Web Crypto as an independent implementation.
  • Decay calculator: step-by-step breakdown (h, exponent -t/h, 2 to that power, percent) plus a five-point table at t = 0, h/2, h, 2h, 4h. Same formula and presets as the memory-gate demo; the breakdown display is new here.
