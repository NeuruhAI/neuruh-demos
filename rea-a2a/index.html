Neuruh Real Estate Agent-to-Agent Protocol

One orchestrator takes a real estate mission in, routes it through specialist agents in order, and records every step with a hash-chained receipt. Nothing makes an offer on its own.

Open the live console

real-estate-agent-c03.pages.dev is the working console for this system. This page is the static protocol surface that describes how it works.

How a mission flows

  1. 1. Mission Intake. A mission starts with an address or parcel, a deal type, and a goal. Intake classifies the mission and produces an ordered run plan. The first step in the plan is always Lead Gen.
  2. 2. Agent Router. The router classifies the mission and proposes a run plan. The run order is: Lead Gen, Inventory, Audit, Context (SREIC), Underwriting engines per deal type, Title gate for distressed-title only, DeedSonar forensic dossier, then Verdict. Lead Gen is step 1 in every plan.
  3. 3. Sequential delegation. Each specialist finishes its step and hands the mission back with its findings before the next specialist starts. No specialist runs in parallel and no step is skipped.
  4. 4. Hash-chained receipts. Every step leaves a SHA-256 receipt chained to the one before it, so the full run can be checked step by step after the fact.
  5. 5. Verdict. Every run ends with the verdict: VERDICT: HOLD. offer_authorized: false. No offer is made without Jeramie.
Verdict, exactly as the console states it: VERDICT: HOLD. offer_authorized: false. No offer is made without Jeramie.

Plain statement: the specialist agents are stubs until the real modules expose A2A endpoints. There is no live data here and no offers are made. This page describes the protocol; it does not run it. The router is a fixed classification table mapping each deal type to its underwriting engines, not a model.

What runs where

The Python services are the live system. The orchestrator runs on port 8000 and the specialists run on ports 8001 through 8004. Those services need a host. GitHub Pages serves only this static surface: this page and the three machine-readable files below.

  • Orchestrator A2A endpoint: http://localhost:8000/a2a/v1
  • Specialists: ports 8001, 8002, 8003, 8004
  • This surface: static HTML and JSON on GitHub Pages, no server code

Machine-readable files

  • agent-card.json : A2A Agent Card for the Neuruh Real Estate Orchestrator, version 0.2.0.
  • raia.json : RAIA registration record for org-us-neuruh, unverified, max data level 0.
  • poppy.json : Poppy protocol record pointing at the live console.

These files describe the same orchestrator in three registries. The endpoint addresses in them are localhost addresses for the Python services, not public URLs.
