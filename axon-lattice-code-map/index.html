4 · Why some counts move run to run

projection.py computes each vertical's entry row as abs(hash(vertical_name)) % height. Python salts string hashing per process, so entry rows differ every run, and shortcut counts that depend on them move with it. The structural assertions do not move: tagged 3.01 vs untagged 4.73 on both runs, tag specificity exact, fallback floor 4.73 on both runs, isolation 168/306 exact, speedup tick 5 vs 2 exact, transfer ratio 1.0 exact. Any future re-run should pin PYTHONHASHSEED for exact count reproduction, or compare ratios and floors, not raw counts.

5 · Tarball reconciliation

The tarball holds 69 entries, 29 Python files — the transcript's "29 Python files" claim is correct (23 code/demo/test files + 6 package __init__.py files). The loose zips hold 24 files total, 19 of them Python, and are an earlier snapshot than the tarball: the loose abstract_lattice.py and projection.py lack the Conditional Shortcut Layer, the loose README is Phase-1-only (4,625 B vs 8,557 B), and the loose config is Phase-1-only (2,695 B vs 4,556 B). The "finish" phase files the transcript named are all in the tarball: conditional_shortcuts.py, substrate_bridge.py, ncp_adapter.py, plus test_conditional.py. Nothing named in the transcript is missing. Four files differ between loose and tarball (abstract_lattice.py, projection.py, README.md, config.yaml); in each case the tarball is the later finished version.
