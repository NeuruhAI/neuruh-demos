The scheme

One ID format for everything:

NRH-[DD]-[ENT]-[TTT]-[NNN]-[hash8]

SegmentMeaningExample
NRHFixed prefix: Neuruh RegistryNRH
DDDomain, 2 lettersRE — Real Estate Intelligence
ENTEntity, 3–4 charactersDSNR — DeedSonar
TTTType, 3 lettersDEP — deployment
NNNSequence, 3 digits001
hash8First 8 hex chars of SHA-256 of the canonical content, NRH tokens stripped4674604a

Regex: NRH-[A-Z]{2}-[A-Z0-9]{3,4}-[A-Z]{3}-[0-9]{3}-[0-9a-f]{8}

Worked example: NRH-RE-DSNR-DEP-001-4674604a — Real Estate, DeedSonar, Deployment, 001, content hash 4674604a.

The hash self-reference fix (SPEC R2)

The hash is SHA-256 of the canonical content with all NRH tokens stripped. Hashing a record that contains its own ID never converges: change the hash and the content changes, change the content and the hash changes. Stripping the NRH tokens before hashing breaks the loop. The hash therefore verifies the content, not the identifier.

Example: 4674604a = SHA-256(merge commit tree) for the DeedSonar production merge.

SKU is not a Registry ID

Registry IDSKU
ScopeInternal. Everything gets one.External. Only sellable things get one.
Shown to a customer?Never.Yes — it is the sellable label.

ExamplesNRH-RE-DSNR-DEP-001-4674604aLANDOS-SCORE-PRO, BIRDDOG-CAPTURE-TEAM, CRUCIBLE-GATE-ENT

A sellable thing carries both: a Registry ID for internal addressing and a SKU for the market. The SKU brand segment swaps under white label; the Registry ID never changes.
