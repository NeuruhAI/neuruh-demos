The founder gate is approved with a name string. Do not call this production ready.

02What was built

  • sovereign_runtime/codex.py: the 13 invariants, 5 state levels, lifecycle order, authority allowlist, resource caps, link threshold 0.15, cascade decay 0.6, depth 3, floor 0.05, signal score weights.
  • sovereign_runtime/models.py: Pydantic models for Capsule, Link, CascadeTouch, Receipt, FounderGate, and InvariantVerdict. Capsule state must be one of the five levels; lifecycle must be DRAFT, ACTIVE, SUPERSEDED, or RETIRED.
  • sovereign_runtime/invariants.py: all 13 invariants mapped to enforceable checks. Halts stop ingestion with a rejection receipt. Gates open a founder gate and hold the capsule. Never a fake pass.
  • sovereign_runtime/store.py: SQLite persistence: capsules, links, an append-only event log, founder gates, meta. Hash-chained receipts using the same canonical JSON scheme as the ontology runtime, so the two ledgers share one receipt format. Chain verification recomputes every hash.
  • sovereign_runtime/engine.py: the compounding engine: atomize, invariant gate, computed signal score, Jaccard linking, decay cascade, founder gate decide and ingest-held, archive through an approved gate, rescoring.
  • sovereign_runtime/watcher.py: inbox watcher with a configurable workspace path. Ingested files move to archive. Files that open a founder gate move to held. Files that halt move to rejected. A held or rejected file never re-triggers on the next poll.
  • sovereign_runtime/cli.py: python -m sovereign_runtime init | ingest | watch | status | gates | verify.
  • tests/: 58 tests covering term extraction, Jaccard math, signal score formula, cascade decay to the fourth decimal, all 13 invariants, gate approve and deny, receipt chain validity and tampering, restart persistence, and watcher behavior.
  • scripts/run_e2e.py: the end-to-end execution that produced the receipt below, including the restart proof.

Run it locally: python -m venv .venv && .venv/bin/pip install -r requirements.txt && .venv/bin/python -m pytest tests/ -q, then .venv/bin/python scripts/run_e2e.py. Watch an inbox with .venv/bin/python -m sovereign_runtime --workspace ~/neuruh-workspace watch.

03The thirteen invariants, as enforced

Every invariant maps to a check the engine runs on every ingestion, in order. HALT stops ingestion and writes a rejection receipt. GATE opens a founder gate and holds the capsule until a founder decides.

IDInvariantEnforceable checkOn failure
INV-01Identity is singularOne canonical id, one capsule. A second capsule claiming an id that exists with different content halts. Identical content under the same id halts as a duplicate.HALT
INV-02State is explicitThe capsule must declare one of the five state levels. No state means no ingestion.HALT
INV-03Evidence is traceableAt least one evidence ref, and a non-empty source ref. No source means no ingestion.HALT
INV-04Authority is boundedThe writer must be a known authority: sovereign-runtime, jeramie-hicks, or founder. Anything else halts.HALT
INV-05Resources are finiteRaw content capped at 50,000 bytes, terms capped at 400. Over either cap halts.HALT
INV-06Context changes weightA signal score is only valid against the corpus version it was computed from. A stale score halts until rescored.HALT
INV-07Learning is governedLinks and cascade updates are only written by the engine through receipts. A draft without an engine receipt marker halts, and a link write without a receipt id is refused.HALT
INV-08Irreversibility needs stronger evidenceArchive and delete are never executed automatically. They open a founder gate.GATE
INV-09Every object has a lifecycleLifecycle must be DRAFT, ACTIVE, SUPERSEDED, or RETIRED, and transitions only move forward. A backward move halts.HALT
INV-10No core forksIdentical content under a different id is duplicate truth. The founder picks the canonical id.GATE
INV-11Outcomes outrank narrativesAn outcome claim must cite an observed receipt id in its evidence. A narrative claim with no receipt opens a founder gate.GATE
INV-12Negative evidence stays visibleA capsule update may not drop a conflict unless it records the superseding receipt. Dropping one silently halts.HALT
INV-13Complexity must pay rentTerms over 400 or links over 10 must be split. Over either cap halts.HALT

04Signal score, computed

The paste hardcoded 90.0 on every capsule. The score here is computed from the live corpus at ingestion time:

novelty = 1 - max Jaccard similarity to any existing capsule
          (1.0 when the corpus is empty)
link_density = min(1, number of links / 5)
signal_score = round(100 * (0.6 * novelty + 0.4 * link_density), 2)

Worked numbers from the end-to-end run: the first capsule ingested scores 60.0 (novelty 1.0, no links yet). The most connected capsule, validation-loop with 6 links, scores 85.14. A capsule identical to one already stored scores 0 on novelty and halts on INV-01 before a score is ever written. Scores are stamped with the corpus version they were computed against; INV-06 halts a stale score until it is rescored.

05The decay cascade, for real

When a new capsule links to an existing capsule at hop 1 with strength s, the update propagates to that capsule's neighbors at hop 2 with strength s * 0.6, and to their neighbors at hop 3 with strength s * 0.36. Propagation stops at depth 3 and below strength 0.05. A capsule reachable by several paths keeps the strongest value. The source capsule is never a cascade target. Every touch is recorded on the capsule and in its own receipt.

End-to-end numbers: 28 cascade touches, max hop 3, total propagated strength 5.6336. The cascade reached hop 3 because the graph has a sparse edge: the advertising index links only to the design index, so updates flow design to advertising to the rest of the graph through the decay.

08Mac run-book

On the M1 Mac, the workspace is ~/neuruh-workspace. Exact commands:

cd ~/workspace/sovereign-runtime
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m sovereign_runtime --workspace ~/neuruh-workspace init
.venv/bin/python -m sovereign_runtime --workspace ~/neuruh-workspace ingest
.venv/bin/python -m sovereign_runtime --workspace ~/neuruh-workspace watch
.venv/bin/python -m sovereign_runtime --workspace ~/neuruh-workspace status
.venv/bin/python -m sovereign_runtime --workspace ~/neuruh-workspace verify

Drop any raw text file into ~/neuruh-workspace/inbox/. Processed files move to ~/neuruh-workspace/store/archive/. Files that open a founder gate move to ~/neuruh-workspace/store/held/. Files that halt move to ~/neuruh-workspace/store/rejected/. Receipts live in ~/neuruh-workspace/store/capsules.db.

File convention: a line starting with OUTCOME: means the dump claims an outcome. Without an observed receipt in evidence, INV-11 holds it for a founder decision. List pending gates with gates, approve one with gates --decide gate-XXXX --approve --by "Jeramie Hicks", then re-ingest the held file.

09What is still missing for production

  • Event bus: the receipt log is one SQLite file. A live multi-agent deployment needs a durable broker (Kafka, NATS) so external agents stream outcomes back automatically.
  • Orchestration and adapters: no MCP gateway, no API adapters, no Temporal or equivalent. Long-running work suspends on a founder gate in SQLite, but there is no durable workflow engine resuming it across process restarts.
  • Identity and authorization: no IAM, RBAC, or signed capability tokens. The founder gate is approved with a name string. A rogue caller with shell access can approve any gate.
  • Notification bus: a held founder gate waits silently. There is no Slack, SMS, email, or approval UI dispatching it and resuming on reply.
  • Verification runners: tests and invariant checks run at build and ingestion time. There are no webhook listeners promoting observed to verified from the outside world (Stripe confirmations, database row checks).
  • Real-time middleware: the engine path is fully gated, but a direct SQLite write bypasses the gate. True middleware would intercept every state transition, not just engine ingestion.
  • Deployment: no hosted deployment, no backups, no monitoring. One file on one machine.
