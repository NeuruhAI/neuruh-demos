5. Lease lifecycle simulator

Deterministic tick engine. No timers, no randomness. Each tick: steps whose dependencies are complete are granted a lease; leased steps send one heartbeat and do one tick of work; a missed heartbeat or a lease expiry with work remaining expires the lease (one retry, then blocked). Completed steps seal a receipt in section 6. Ticks are exact and repeatable: the same mission always produces the same log.

6. Receipt chain

Each completed step seals one receipt. A receipt records its index, mission ID, step, event, tick, the previous receipt hash, and its own hash. The hash is SHA-256 via Web Crypto where available; where Web Crypto is unavailable (for example in the jsdom test run) a deterministic fallback hash is used instead, and the algorithm is printed on every receipt so the difference is visible. The genesis previous-hash is 64 zeroes. Tamper with nothing: the verify button recomputes every hash from the stored canonical string and checks every link.

7. Share by link

The mission definition (name, World, steps with dependencies) is encoded as base64 JSON in the URL hash. Opening the link restores the same mission. Simulation state (tick, leases, receipts, log) is not shared; the recipient re-runs the deterministic simulation.

On load, this page reads the #d= hash first. If it is present and parses, the shared mission replaces the empty default. If it is malformed, the page keeps the default and reports the failure here: no hash present on load

9. How it works / What this is not

How it works

  1. Compose. Name a mission, pick a World, add steps with a role, a work duration, a lease length, and dependencies. The DAG view draws the graph by dependency depth.
  2. Validate. The validator runs Kahn topological sort. If the sorted count is short of the step count, a cycle exists and a depth-first search names the steps in the cycle. A broken DAG cannot simulate.
  3. Simulate. Each tick grants leases to steps whose dependencies are complete, then advances each leased step by one heartbeat and one work tick. Lease length must cover work; a missed heartbeat or an expiry with work left expires the lease. One retry, then blocked. Blocked steps block their dependents.
  4. Seal receipts. Each completed step seals a hash-chained receipt: index, mission ID, step, event, tick, previous hash, hash. The chain links every receipt to the one before it, back to a 64-zero genesis.
  5. Verify. The verify button recomputes every receipt hash from its stored canonical string and checks every previous-hash link. Any mismatch is reported by receipt index.
  6. Share. The mission definition encodes to base64 JSON in the URL hash. The link restores the mission on load; the simulation re-runs deterministically from tick 0.

What this is not

  • Not a live swarm. No workers run here, no leases exist here, no runtime state is shown. The simulator is a deterministic tick model in the browser.
  • Not a second assistant or a new orchestrator. Per V2, Copilot is a skin over Presence/LARIC and BOB compiles missions on the existing Founder Runtime. This page compiles nothing and orchestrates nothing outside itself.
  • Not a new swarm server, not a new database for Worlds, not 5,150 always-on agents. The V2 blueprint forbids all three. This page stores state only in memory and in the URL hash.
  • Not a deployment. This page authorizes no merge, deploy, runtime mutation, or new authority. It is staged only.
  • Not proof of the donor claims. Donor metrics, revenue, and legion counts are historical, simulated, or hardcoded in the source material. The 5,150 figure is a design target, never live sessions.
  • Not a replacement for the source document. Read the V2 DOCX for the full 61 tables, the custody record, and the acceptance courts. This demo covers sections 6 and 8 plus the count discipline of Tables 8 and 16.

10. Honest gaps

What the sources do not define, what conflicts, or what could not be verified for this build.

  • No lease, DAG, or receipt schema exists in the sources. No worker-lease, mission-DAG, or receipt schema file for the swarm runtime was found (runtime-scoping.md, SWARM section). The demo schema here (step fields, tick model, one retry, receipt field list, genesis value) is invented for this demo and labeled as such. It is not a source schema.
  • No tick numbers in the sources. V2 defines lease states and event names but no lease durations, heartbeat intervals, expiry policy, or retry count. The durations, lease lengths, and the one-retry rule in this demo are demo choices.
  • Donor counts conflict. The donor legion table sums to 5,150; the same donor material elsewhere says 5,000 agents and 5,000+ Durable Objects; the architecture blueprint separately proposes a 10,000+ worker infrastructure. V2 rules all three as donor logical capacity. This demo repeats the ruling and does not reconcile the figures, because the sources do not.
  • Three donor runtimes, unreconciled. The architecture blueprint contains at least three different proposed runtimes (Cloudflare Workers/Durable Objects swarm, PMLA MCP mesh, Cloudflare Sovereign Mesh). No one is selected as canonical in the sources, and no repo, branch, or deployment for any of them is named as live.
  • Donor duplication flagged, not collapsed. The V2 document lists the seven historical legions twice (Table 14 and Table 44) with slightly different modern mappings: Counter-Intel is "Market/competitor/risk intelligence" in one and "market/competition/risk observation only" in the other. The "do not start with" list also repeats in sections 13 and 32. This demo follows the Table 14 wording for role labels and notes the difference here instead of silently picking one.
  • PR merge status UNKNOWN. Research Swarm PR #8, AXON Context MUX PR #6, and Atomic taxonomy PR #1 are cited as candidates. Whether any is merged, open, or stale was not verified in this build.
  • World Emitter unwired. V2 states World Emitter is explicitly unwired in current Cockpit ownership. This demo draws no World Emitter path and claims none.
  • End-to-end auto-Sentinel/result-ingest NOT LIVE-PROVEN. V2 classifies it as not live-proven. This demo simulates a court step as a labeled step only; no court runs.
  • No live data. Nothing here reads Cockpit, Workers, Switchboard, Galaxy, Vault, or any live Neuruh system. Live state of AXON, Workers/Switchboard, BOB, Sentinel, and Vault was not re-verified for this build.
  • Receipts are demo receipts. The chain proves internal consistency of this page's own simulation only. It is not Vault custody, not HONEY Git custody, and not a Sentinel court record.
  • Fallback hash. Where Web Crypto is unavailable, receipts use a deterministic fallback hash (cyrb53, 256-bit output) instead of SHA-256. The algorithm is printed on every receipt. A fallback receipt is not a SHA-256 receipt.
  • Layout not eyeballed in a real browser. Verified in jsdom only (DOM checks, exact hand-computed values). Visual polish in a real browser is unconfirmed.
