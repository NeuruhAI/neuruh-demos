Sep-7 protocol

Topology-to-outcome experiment bench

Does changing the computational organization around the same mission change measured results? Run the comparison protocol: same mission class, five organizations, repeated trials. One successful run proves nothing; this bench refuses to crown a winner under 10 trials per variant.

Pre-outcome record is captured for every trial before execution: archetype, success condition, evidence, prediction, confidence, expected cost and latency, provider, recipe, topology, tools, alternatives, unknowns.

Sep-7 · Reasoning compilation

Successful intelligence should get cheaper

Repeated successful reasoning compiles downward into cheaper logic. Run the same classification task repeatedly: each clean run is evidence. At the thresholds, promote the pattern down a rung. A novel or ambiguous case routes straight back to frontier reasoning. Ambiguity is never compiled away.

Walkthrough

Presenter script

Six moves, about four minutes. Every claim below is something the console actually does on screen.

  1. Seal a forecast."Before anything executes, the prediction is locked: class, confidence, cost, latency, recipe, topology, known unknowns. The seal hash is the receipt. This is the input the whole architecture was starving for."
  2. Execute, then hit hindsight."Run the mission and the outcome pairs. Now run one without a forecast. Same outcome quality, and calibration refuses it. Learning from hindsight is narrative, not measurement."
  3. Build three pairs and read the chart."Stated confidence against observed outcomes. The gap is calibration error, per recipe, per source, per topology. That gap is what gets governed."
  4. Draft the proposal, convene the court."Learning proposes; it does not edit. The court checks pairs, Brier score, and boundary. Governance promotes a version, or rejects it, with the reason in the log."
  5. Run the topology bench at 1 trial, then 12."At one trial the bench refuses to declare a winner. At twelve, differences become evidence. That refusal is the difference between a research program and a success story."
  6. Feed it unserved demand, then compile a pattern down."The second loop: buyers pull the build queue through MISSING_INGREDIENT and RICHIE ranking. And every repeated success gets cheaper, rung by rung, without ever compiling ambiguity away."
