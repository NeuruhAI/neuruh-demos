06Debt terms, DSCR, and cash flow

DSCR bands are the builder's design: below 1.00 is a kill, 1.00 to 1.25 is thin, 1.25 and above is the lender comfort zone.

12How it works / What this is not / Sources

Read this before relying on any number on this page.

How it works: confirm the address and parcel from at least 2 public sources, enter the rent roll unit by unit with a grade per unit, enter actual and stabilized income and expenses, enter a sourced cap rate and stated debt terms. The tool computes NOI actual and stabilized, stabilized value and a cap-rate value range, value per unit, DSCR at the stated debt terms, cash flow and cash-on-cash, and deferred maintenance by unit. Gates fail closed. A kill means PASS. The receipt records what was entered, what passed, and what was N/A. A share link encodes the whole deal in the URL so someone else can open the same numbers.

What this is not: not an appraisal, not a valuation, not a survey, not legal, tax, or lending advice, and not a replacement for lease review, bank deposit verification, a title commitment, an inspection, or a licensed professional. It does not invent rents, leases, expenses, cap rates, or prices. If a field cannot be verified, it stays N/A. No offer is quoted without Jeramie. It presents no recommendation to buy or sell.

Builder design decisions (mine, not paper claims, not Jeramie's order):

  • Scope is 2 to 4 units (duplex, triplex, fourplex). The 2026-11-04 E2 build scoped 2 to about 20 units. This build follows the E-series 2 to 4 unit definition in the build order. The difference is stated here, not hidden.
  • Builder defaults, all editable: vacancy allowance 5 percent, management 8 percent of EGI, cap rate 7.00 percent, value range spread 0.5 percentage points around the cap rate, DSCR thin band 1.00 to 1.25, comfort at 1.25 and above. None of these is a market fact.
  • Receipt v1.0 uses a SHA-256 chain with GENESIS as the first prev_hash, canonical JSON with sorted keys and the hash field stripped, and an in-browser Verify button using Web Crypto. The E1, Residential, and 2026-11-04 E2 receipts had no hash chain; the chain is new in this build.
  • Cap-rate-implied value is shown as a range (cap rate plus and minus 0.5pp) in addition to the point value, so a small cap rate error is visible instead of hidden.

13Honest gaps and limits

What this engine does not do, stated plainly.

  • No live data connection. Rents, leases, expenses, cap rates, and debt terms are entered by hand and are only as good as their sources.
  • No lease review. Grades are self-reported. A grade A unit still needs the signed lease read, and bank deposits checked against the rent roll.
  • No expense audit. Owner T12s can understate expenses. Taxes, insurance, and utilities should be verified against bills, not the seller summary.
  • No market rent verification. Market rents need named rent comps with sources. This engine does not fetch them.
  • No title, lien, or heir check. Title risk is a gate flag here only. Distressed title needs E8.
  • No physical inspection. Deferred maintenance is an entered estimate, not an inspection report.
  • Cap rate is an input, not a computed market fact. A wrong cap rate moves value more than any other single input. The value range shows that sensitivity; it does not fix it.
  • Break-even occupancy is a simple arithmetic check at stabilized gross rent. It does not model lease-up timing or rent concessions.
  • Cash flow is before tax and before reserves timing. It is not a tax or investment return claim.
  • Receipts live in this browser session only. Closing the page clears the chain. Export the receipt JSON for the file copy.
  • Layout was not eyeballed in a real browser. The page was tested with Node tests plus code inspection only.
