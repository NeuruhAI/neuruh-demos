FIG. 2The P0 pivot chain — one LLC in, the whole portfolio out

  1. 1 · Owner-LLC — the starting entity. A parcel's owner of record is usually an LLC, not a person.
  2. 2 · Registered Agent + Officers — the LLC-piercing step. Michigan MiBusiness Registry Portal (replaced legacy COFS 2025-06-23) and Indiana INBiz public search; the portal's individual-name search (Begins With / Exact / Keyword / Soundex) is the reverse pivot. No official REST API — automated portal querying.
  3. 3 · The human — the natural person behind the agent / officer roles.
  4. 4 · Their other LLCs — every other entity the same human is tied to, resolved in-graph.
  5. 5 · Every parcel in their portfolio — all parcels those LLCs own, via :OWNS edges. Regrid owner-name search is still a work in progress, so this step resolves in-graph plus ATTOM, not through Regrid.
  6. 6 · Distress events on each parcel — probate, lien, tax delinquency, code violation, eviction — attached as entities, so the score and the story meet on the same node.

Figure 2 — The priority pivot set confirmed June 2026. The resolver is built and tested before any connector, because a bad entity merge corrupts every investigation downstream.

FIG. 3One engine, three packs — the dual-use argument

Pack 001 · Real Estate LIVE SCOPE

Seller-hunting: LLC → human → full portfolio → distress. The pack this build ships first.

Pack 002 · Threat Intel SAME ENGINE

Threat-actor mapping on the same substrate: swap the entity pack and the transform pack, keep the resolver, the cache, and the canvas.

Pack 003 · KYB / AML SAME ENGINE

Fraud-ring tracing and Customer Due Diligence. Federal CTA beneficial-ownership reporting suspended for 2026, so state-registry resolution is the operational CDD baseline — a second product surface for the same code.

Figure 3 — The pack-agnostic core. Real estate is pack 001; the engine does not change when the pack does.

FIG. 4One backend, two canvases — the Bloom / NVL split

Bloom — internal cockpit

Ships only with Neo4j Enterprise Edition. It is the internal investigation cockpit, free via Neo4j Desktop for a single user. It cannot ship inside a white-label product without per-seat Enterprise licensing, which would gut the resale margin.

NVL — white-label canvas

The Neo4j Visualization Library is the exact engine that powers Bloom, free on npm, usable in any app that connects to a Neo4j database without additional Neo4j licenses. Bloom-grade rendering, fully brandable, resale-ready. This is the canvas that ships to tenants.

Figure 4 — Verified June 2026 against Neo4j's bundle notes and the NVL docs. The split resolves the internal-and-white-label answer: one Neo4j 5.26 LTS backend, two licensing lanes.

Build record (June 2026)

Path C chosen — backend now, light viz later. Path A (custom transforms on real Maltego) rejected: rented frontend, not white-label, cannot resell. Path B (full bespoke engine) is the end state, deferred. Stack: Neo4j 5.26 LTS, Cypher 5, ARM64 Docker, Redis (not /dev/shm — the RAM-disk is Linux-only and fights Apple-Silicon unified memory), FastAPI transform engine, REST surface. Runtime: Colima over Docker Desktop — Colima fences the VM (--memory 4) so Neo4j + Redis cannot starve local MLX inference (Bonsai :8100, Gemma :8200, AXON :7331) on the same unified-memory box. Bare colima start defaults to 2GB and would OOM Neo4j. One-shot package: BUILD_SPEC.md, CLAUDE.md, schema.cypher (74 lines), .env.example (66 lines). Data: Regrid for parcels/geometry/situs (~200 req/min); ATTOM for ownership depth, deeds, mortgages, liens (30-day free trial); MI MiBusiness Portal and IN INBiz free public search for the LLC-piercing pivot (IN bulk download is $9,500, so the free portal is scraped instead). Open on Jeramie: the Tracerfy connector shape lives in the APG-CRM repo (Claude Code needs to see it for Phase 3); the repo name landgraph is a placeholder; CLAUDE.md still says Docker Desktop and needs the Colima patch.
