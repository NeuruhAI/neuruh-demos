# Code and data sharing map (convergence spec item 12)

First pass, 2026-11-15. Purpose: a change in one demo can be traced to the
others that share its code or data. The anchor's own sharing is complete
below. The estate families are the documented shared pieces from the
doubt-removal audit and the build notes; a full 178-demo sharing audit
(reading every page's scripts) is a separate job and is recorded as open,
not claimed done.

## The anchor's own sharing (complete)

| Shared piece | Used by | Change impact |
|---|---|---|
| `verify.js` | The anchor page (loaded as `<script src="verify.js">`), the downloadable verifier (the same file), `ci_check.sh` (jsdom root recompute), the page's tamper demo and receipt-chain verifier | Any change to the canonicalization or Merkle rules must be mirrored in `build_anchor_v2.py` and `test_vectors.py`, and the manifest's `verifier.sha256` pin must be rebuilt. The CI check fails on divergence. |
| `manifest-v2.json` | The anchor page (fetched at runtime), `verify_membership.py`, `audit_anchor.py`, `ci_refetch.py`, the status endpoint (`status.json`) | A new manifest version re-roots every receipt that carries `merkle_root`. Old roots are retained in `CHANGELOG.md` (re-anchor policy). |
| `receipt-schema.json` (v1.1) | `verify.js`, `receipts.py`, `verify_receipts.py`, `brier.py` (forecast/outcome receipts wrap a record hash in a canonical receipt) | A schema change requires all four implementations to move together; the tamper harness (8 attacks) must still pass. |
| `canonicalization` (CANONICALIZATION.md) | `verify.js`, `build_anchor_v2.py`, `test_vectors.py`, `receipts.py`, `observation.py`, `brier.py` | The byte-level rule is the single point of agreement. Any change breaks cross-language root equality (finish criterion 1) and must be versioned. |
| `brier.json` | The anchor page's calibration dashboard, `status.json` (`last_brier`) | Regenerated when the Measurement Loop resolves forecasts. Each manifest version re-commits the current Brier (convergence item 84). |
| `observations-pilot.jsonl` | The anchor's Section E integration, the Measurement Loop page (authoritative source) | The anchor copy is verified against the loop page (25/25 valid). A new loop sample replaces this file and its manifest leaf. |
| `demo-inventory.json` | The anchor page (inventory link), the manifest (as a ledger leaf), the hub-card verification data (`hub-card-verification.json`) | Regenerated by the builder on every manifest rebuild. Its hash is a manifest leaf (convergence item 10). |
