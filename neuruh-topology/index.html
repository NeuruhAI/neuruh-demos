Chain rule. The first receipt's prev_receipt_hash is the string GENESIS. Every later receipt's prev_receipt_hash equals the previous receipt's receipt_hash. A link passes when the hash recomputes AND its prev hash equals the previous receipt hash. A broken link returns TAMPERED.

Hash rule. Each receipt_hash is SHA-256 of the canonical record for that stage (sorted keys, no whitespace). The packet hash is SHA-256 of the canonical packet. The On-Chain Anchor commits to the same bytes: its Merkle leaves are SHA-256 of the canonical JSON of each manifest entry, and its root is SHA-256 over the concatenated raw 32-byte child hashes, duplicating the last node on an odd level.

What the format does not do. A valid receipt proves the run happened in the page as recorded. It does not prove the underlying claim is true, the data is live, or the system is in production. A receipt from a SIMULATION page is a simulation receipt, and it says so in the packet's tool field.

9. How to traverse the machine

The connections this page wires, in the order a person walks them:

  1. Start at the hub (neuruh-hub.pages.dev): the registry of all 182 sites, v2.56.
  2. Pick a system in the Unified Swarm registry (unified-swarm): search by legion, stage, or host; every system has its live link.
  3. See the same system as a solution card in the Solution Swarm (solution-swarm): its two polarities, its threat reading, its emergent third thing, its receipt. Confirm or reject a hit and watch the weights and the messages move.
  4. Run a signal through the Threat Deterrence Console (threat-deterrence-console): paste a message, score it, check the bot farm detector, file a resolution intake and get a case packet.
  5. Run a claim through the Unified Chain (unified-chain): nine stages, one chained receipt, tamper test.
  6. Verify the receipt chain in the Receipt-Chain Explorer (receipt-chain-explorer): paste the chain, watch each link pass or fail.
  7. Check the anchor (onchain-anchor): the Merkle root over 195 artifacts, and the verifier that proves membership by Merkle path.
  8. Read the problems the machine is aimed at in the Hard Problems Atlas (in flight): 150 problems plus typologies, each mapped to the estate with measurable indicators and the Daybreak adapter flow.

The Daybreak adapter (N43) is the one new build the adaptation map calls for. Everything else in the traversal already exists as a page; the work is wiring, not invention. The adapter's input is a finding, its output is a gated patch, its proof is a retest and an outcome code, and its export is a receipt in the format of section 8.
