World Seeder Loop

The autonomous World Seeder of May 9-10, 2026, as a working loop you can run in the browser: connector reads the graph, seeder detects clusters and drafts Worlds, activator scaffolds repos, feedback loop adjusts the threshold. Everything on this page comes from the Batch 016 dossier. Nothing the dossier says was never recovered is invented here.

1. The pipeline

Four scripts, chained by cron, each feeding the next. The value is not the nodes (the facts) and not the scoring (the emergence number). It is the edge-drawing that surfaces a cluster no one had named yet. A node is a context-poor fact; the intelligence is in which edges get drawn between nodes that were not connected before.

2AM
connector.py

Scans all nodes, scores edges, writes YYYY-MM-DD-edges.json, injects wikilinks (top 200 edges, max 5 links per node).

3AM
world_seeder.py

Reads edges, detects clusters, Claude drafts Worlds, writes .md to the vault and files to Notion. Skips emergence below 40 and Worlds that already exist.

3AM+
world_activator.py

Scaffolds GitHub repos for Worlds scoring above 85. Full text never recovered; the gate is known, the code is not.

SUN 4AM
feedback_loop.py

Self-adjusts the emergence threshold from prediction accuracy. The threshold it adjusts is the 40 floor in the seeder.

Two gates that are NOT the same: the activator's above-85 scaffold gate, and batch 010's emergence gate (doctrine-eta at or above 70 AND feedback accuracy at or above 0.6). Do not merge them.

Do not conflate the seeders. The January 2026 static builder (neuruh_vault_builder.py, hardcoded SEEDER_NODES dict) is NOT this system. This demo is the May 9-10 autonomous seeder only.

2. The May 9 result, with the CRUCIBLE tension

On May 9 the seeder autonomously detected 4 clusters from 500 edges and created 4 Worlds with zero human input. All 4 were filed to the Notion IP Registry with real page IDs, a Slack report was sent, and git was committed. Verdict on the run itself: HISTORICAL (transcript-recorded, not re-verified against files here).

The tension, stated on the page. The seeder's emergence scores are exactly the self-graded scores CRUCIBLE was built to kill. The recovered prompt asks the model to draft the World and then score its own draft's emergence from 1 to 100. Nothing external enters the number. The batch 015 CRUCIBLE critique records that every auto-generated World lands 87-94, so the score carries zero information: a rubber stamp wearing a lab coat. The pipeline ran. The 87-94 band is not evidence of quality. Both can be true at once.

CRUCIBLE gate used below: score = max(0, emergence - objections) x multiplier. Multipliers: signed contract 1.00, paid pilot 0.50, one real lead 0.30, no signal 0.15. Verdicts: below 20 KILL, 20-49 ITERATE, 50 or above with a real external signal SHIP-CANDIDATE, 50 or above without one ITERATE. Objections are 0 for all four Worlds because no adversary pass was ever run: zero objections RECORDED, not zero found. With no external signal the multiplier is 0.15, so even a perfect self-score of 100 tops out at 15, below the KILL line.

3. The data contract, and the May 12 bug

The edges file does not use source / target at the top level. It nests the real data under top_edges, holding the top 50 of 500 edges. Fields per edge: from, to, from_title, to_title, score, shared_keywords, vertical_match. Correct read: data["top_edges"], then e["from"] / e["from_title"] per edge. Anything reading e["source"] or e["from"] at the top level parses 0 edges. That was the May 12 bug: 500 edges found, 0 parsed.

7. Failure points to not repeat

  
    
    
  1. Cron env starvation. Cron did not inherit shell env, so credentials were missing overnight and jobs failed silently. Fix that shipped: ~/.neuruh_env holding all secrets, SHELL=/bin/zsh at the top of crontab, every job sources the env file first.
    2. 
    
  2. Edge schema drift. Section 3. Half the downstream bugs were code reading the wrong keys (source / target at top level instead of top_edges to from).
    3. 
    
  3. Blank ip_title. Real-estate nodes exported from Notion with empty titles because the property name did not match what the seeder expected. A patch script backfills titles from asset_id.
    4. 
  

  
Rebuild rules stated in the transcript: nothing destructive, nothing overwrites the current _scripts/ without a diff shown first; the rebuild is additive. Vault layout the seeder reads and writes (June 11, 2026 state, historical): 03-IP/worlds/ 235 files, core-nodes/ 313, foundation/ 122, specs/ 188, plus _graph/, _scripts/, 01-DAILY-LOG/.
