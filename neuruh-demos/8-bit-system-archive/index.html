The breakthrough is therefore not "eight bits create intelligence". It is: once the operating organization around a model can be consistently encoded, governed, replayed, compared, and connected to outcomes, that organization becomes an optimizable computational object. That is the serious thesis underneath the 8-bit system.

The most defensible classification today is: N-Cell is a proposed runtime state and authority protocol for a governed adaptive computational organization. Its purpose is to give every Neuruh subsystem the same deterministic answers to: what was active, what was connected, what was proposed, what was permitted, what was actually available, what authority survived governance, which memory was accessible, which lifecycle stages were reached, what was blocked, what was emitted, which topology produced the outcome, and what changed from the previous run.

The canonical N-Cell/64 header

Eight unsigned bytes, one 64-bit operational header. Click a byte to read what it records. Representations required by the specification: Uint8Array, a 16-character lowercase hexadecimal string, a 64-character binary string, an unsigned 64-bit integer where the language safely supports it, a structured JSON object, and a human-readable decoded representation.

Canonical field rules

  1. Each field is exactly one unsigned byte from 0 through 255.
  2. Bit registries define the meaning of bits 0 through 7 for mask fields.
  3. Confidence and risk are scalar bytes from 0 through 255.
  4. Unknown or unused bits must remain explicitly reserved.
  5. Bit meaning must never silently change within protocol major version 1.
  6. Registries must be machine-readable and versioned.
  7. Encoding and decoding must be deterministic across TypeScript and Python.
  8. Cross-language fixture parity must be tested.
  9. Invalid values must fail closed.
  10. Unknown schema versions must be rejected unless explicitly supported.

Named types in the specification: NCellHeaderV1, NCellStateV1, NCellEnvelopeV1, NCellReceiptV1, NCellTransitionV1, NCellOutcomeV1, NCellManifestV1, NCellAuthorityDecisionV1, NCellTopologyV1, NCellEvidenceReferenceV1, NCellSignatureV1.

Figure 2: The canonical v1 header from assistant reply 2 and build-prompt section IV. N-Cell is a compact runtime ABI and control-plane fingerprint, not a second orchestrator or replacement for governance, health, evidence, or memory systems.

Default registries for demonstration and conformance. They must be replaceable by domain-specific registered profiles while maintaining protocol compatibility. The specification says clearly: these are default profiles, not universal philosophical truth. Click a mask to read its eight bits.

Authority algebra calculator

Deterministic authority reduction, from build-prompt section VI. Effective authority is the AND of all five masks: requested AND available AND policy-allowed AND operator-allowed AND environment-allowed. Blocked authority is requested AND NOT effective. Toggle bits to see the reduction. The implementation must use byte-safe operations and preserve all intermediate masks in the decision record. N-Cell must record governance outputs; it must not invent governance decisions.

Effective: 11111111 (0xFF). Blocked: 00000000 (0x00).

Authority decisions must contain: requested authority, available authority, policy-allowed authority, operator-allowed authority, environment-allowed authority, effective authority, blocked authority, reasons per blocked bit, policy references, decision timestamp, decision producer, decision version, and a signature or integrity hash when configured.

Figure 4: The authority algebra from build-prompt section VI. This calculator demonstrates the filing's own AND formula on a single byte; the real algebra applies the same operation across the full authority mask.

From the service: Receipt Chain, Observer / Cockpit, Outcome Store, then N-Lab / Optimization. The service does not orchestrate AEGIS, does not replace Governance, and does not replace Vault.

The parity rule. The first implementation must prove: stripNCell(executeWithNCell(request)) === execute(request). That is essential. The first version should observe and encode the existing system, not alter its decisions.

Every N-Cell record needs to be linked to: run ID, world ID, node and organ IDs, code version, manifest hash, topology hash, governance decision, previous receipt hash, outcome reference, and timestamp. Cross-domain adapters are required at minimum for AEGIS, LandOS / DeedSonar, and World Emitter. The observer interface should show current N-Cell, previous N-Cell, XOR delta, active organs, available routes, effective authority, blocked authority, memory scope, lifecycle stage, confidence, risk, outputs, receipt validity, and outcome.
