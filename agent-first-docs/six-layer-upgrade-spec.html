Six-layer upgrade spec, Jeramie, 2026-11-15 06:43 EST

Instruction: "ADD IN." Routed into the Neuruh Bridge/Topology build (as the design for the topology, authority, and verification layers) and the Hard Problems Atlas (as the upgrade-path mapping, each layer mapped to the problems it addresses).

Layer 1: Real observation (replace keyword banks)

  • Define a small set of external data sources with stable schemas (public blockchain explorers, county property records via official APIs or bulk downloads, court dockets, sanctions lists, published scam reports, financial filings).
  • Implement typed connectors that emit canonical observations with provenance (source URL or query, timestamp, hash of raw payload, retrieval method).
  • Store observations in an append-only log that is itself receipted. No observation enters the system without a hash.
  • Start with one narrow domain (e.g., public wallet clusters already labeled in reputable reports, or public LLC formation + property purchase patterns) rather than "everything."

Layer 2: Explicit models and forecasts instead of polarity formulas

  • Replace or supplement the breadth/clarity formula with models that make pre-registered forecasts (probability a wallet cluster is associated with a known pattern, probability a property transaction matches a historical fraud typology, etc.).
  • Require every forecast to be timestamped and stored before the outcome is observed.
  • Score forecasts with proper scoring rules (Brier or logarithmic). Publish the scores.
  • Keep polarity or other simple composites only as interpretable features, not as the final decision.

Layer 3: Authority and action boundaries

  • Every proposed action (alert, report draft, weight update, data fetch) must carry an authority header that states who or what authorized it, the scope, the expiry, and the single-use token or equivalent.
  • Implement a policy gate that can DENY or ESCALATE independently of the model or scoring function. The gate's decision is logged and receipted.
  • Human approval remains mandatory for any action that leaves the system or affects external state. The system can prepare the packet; it cannot send it.

Layer 4: Closed-loop learning that is actually measurable

  • After an outcome is observed (a reported scam is confirmed by authorities, a property pattern is later cited in a case, a forecast is resolved), code the outcome against the original forecast.
  • Update weights or model parameters only when the update is shown to improve calibration on a held-out or subsequent set. Log the before/after Brier or equivalent.
  • Maintain a promotion gate: a change in scoring or topology is only retained if it improves a pre-specified metric on data not used to propose the change.
  • This is recursive in the narrow sense of improving the measurement apparatus. It is not recursive self-modification of arbitrary code.

Layer 5: Communication and topology that is contract-based

  • Define message types with schemas (observation, forecast, receipt, escalation, outcome).
  • Sign or hash-chain messages. Receivers can verify provenance without trusting the sender.
  • Topology becomes a set of active leases or subscriptions rather than a static 7x10 matrix. A "legion" or module only receives messages it is authorized to process.
  • External communication (to a human, to another system, to a reporting endpoint) is an explicit action under Layer 3.

Layer 6: Independent audit and adversarial testing

  • Maintain a parallel verification path that re-computes scores and receipts from the raw observation log. Divergence is a failure.
  • Periodically inject synthetic or historical cases with known outcomes and measure detection and calibration.
  • Publish the verification results. Allow external parties to re-run the receipt chain on exported logs.
  • Red-team the observation connectors and the policy gate separately from the scoring logic.
