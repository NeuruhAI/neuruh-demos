1. How to read the state ladder

The ladder is CONCEPT, DESIGNED, IMPLEMENTED, TESTED, DEPLOYED, LIVE, PROVEN, COMMERCIAL, BLOCKED. Each rung means something different, and this document never upgrades a rung without evidence.

StateMeaning in this document
DESIGNEDArchitecture, doctrine, or prompts exist on paper. No running code is evidenced.
IMPLEMENTEDCode, prompts, or a documented role exists. It has not passed a recorded test run.
TESTEDA recorded test, harness run, or proof run passed. Production use is not claimed.
LIVERunning on a schedule or serving a live page, with a receipt or a verified check dated 2026-11-18.
BLOCKEDA named gap stops it. The reason is given, not smoothed over.
UNKNOWNNo source read for this document establishes the state. Nothing is filled in by guess.

PROVEN is used only where a source records a passed verification with a receipt. COMMERCIAL applies to nothing in this catalog, audit date 2026-11-18. MRR is $0.

4. Mother and Axon

MOTHER is the monitoring and coordination spine. Three versions are on record, and they are not the same thing.

MOTHER v1: System Monitor

MOTHER v1 is the System Monitor and Autonomous Agent for Neuruh. Its single responsibility is to observe the system, detect what is wrong, and make it impossible to miss. It is not a general assistant and not an idea machine. It is the autonomous heartbeat and immune system of the business infrastructure. Its rules, from the recovered prompt in the design filing: truth over comfort, evidence over memory, no silent drift, no false completion, one action at a time, session discipline, conflict first. A task is DONE only when code is committed, deployment is live, a test passes, Notion reflects it, and a receipt exists.

Permissions are narrow by design. MOTHER v1 MAY read Notion pages and databases, GitHub repos, commits, branches, and PRs, local files and session logs, compare states across systems, generate reports and alerts, and propose next actions. It MAY NOT deploy to production without explicit approval, delete data, files, or records, modify canonical documents without approval, contact clients or external parties, or spend money or commit resources. It is the observer, not the operator. Its power is visibility, not control.

MOTHER v2: AXON Coordinator

AXON is the MOTHER v2 Coordinator. It is the brain that routes work and does not do the work itself. It decides who does it, in what order, and how success is measured. Task intake classifies work as BUILD, RESEARCH, DESIGN, SALES, OPS, or RECOVERY, then coordinates specialist agents without collisions. The AXON/MCP execution chain is ROUTER to Coordinator to parallel workers to memory to prompt composition to model routing to Session Scribe to Receipt. AXON also carries the model router, the permission guard, the tool interface standard, logging, and the gateway heartbeat. The AXON Lattice Substrate and AXON Lattice Verified Code Map demos are live on the hub, audit date 2026-11-18, and the model router verification filing is live.

MOTHER v3: control plane

MOTHER v3 is the control plane in the rebuilt design, sitting above MOTHER v2 and the five executive agents. State DESIGNED, audit date 2026-11-18. The Retardio Library chapter 17 lists the Mother/Axon conductor as DESIGNED. No run evidence for v3 is in the sources read.

MOTHER v3 is also described in the standing record as an organism-resilience and monitoring layer with semantic health checking and alerting. That description is a design claim, not a live observation, and is recorded here as such.

5. BOB and the conductors

BOB is the mission scheduler and orchestrator. The swarm filing is explicit that BOB should not become another giant agent that does everything. BOB receives a MissionCapsule and produces a SwarmPlan: objective, priority, dependencies, required evidence, required capabilities, authority class, budget, SLA, and completion contract. The filing gives the example mission "Find highest-value real estate opportunities in Berrien County", decomposed into 4 source hunters, 2 identity resolvers, 3 signal assemblers, 2 valuation workers, 1 title investigator, 1 zoning investigator, 1 contradiction hunter, 1 economic evaluator, and 1 independent court, then parallel execution, evidence graph, candidates, rank, underwriting swarm, and Sentinel.

The audit corrects the record: BOB exists in code as a role, not a service. The switchboard emits promotion.requested and the Honey Pot promotion executor consumes it. There is no autonomous BOB agent and no BOB repo. Any claim of "BOB decided" should read "switchboard emitted; founder approved". State DESIGNED, audit date 2026-11-18.

The swarm architecture gives a path toward making that runtime-generated instead of hand-configured. That path is DESIGNED, not built.

12. SWARM and the seven legions

SWARM is a dynamic swarm execution fabric, not a headcount of running models. The filing's own correction is the controlling line: "Swarm should not mean 5,150 copies of an LLM running around. That part of the document is theater." The correct Neuruh abstraction is 5,150 logical worker identities and capability slots, backed by elastic execution, instantiated only when work exists.
