T1. Volume and parallelism

Agents generate far more change volume than humans, in parallel, around the clock. A review system sized for human pull request rates will drown.

State: PROVEN. Scope: Proven for agent build volume in the overnight run and for lead scoring volume in the 2026-09-16 hunt job. Not yet proven against real pull request volume through a review queue; that part is DESIGNED.

Design consequence: Review must be per change packet, not per comment thread, and must run without a human in the per-packet path. Volume is absorbed by parallel isolated reviewers and a deterministic gate, not by adding human reviewers.

T2. No persistent memory across sessions

Agents forget between sessions. The system must remember for them. The receipt chain is the memory.

State: PROVEN. Scope: Proven that the estate loses context without written receipts (IDENTITY section 19) and that chained receipts survive as memory (Done Ledger chain VALID, 118 receipts). The receipt chain as the sole memory for source control review is IMPLEMENTED in the demo, not yet proven on real reviews.

Design consequence: Every consequential action writes a hash-chained receipt before it counts. Nothing is trusted to an agent's session memory. The chain, not the agent, carries state forward.

T3. Need machine-readable verdicts, not prose

Agents cannot read threads. A verdict must be a value a machine can act on, with the exact failing claims named.

State: IMPLEMENTED. Scope: Implemented as a browser simulation in the phase 1 demo. No real pull request has been reviewed by this verdict format, so it is not PROVEN.

Design consequence: Review output is a verdict enum plus a list of exact failing claims, never a comment thread. The change packet carries the diff, the N-Cell/64 authority header, the claim set and the evidence in one machine-readable unit.

T4. Correlated errors and phantom consensus

Agents converge on each other's errors. Agreement after interaction is not independent confirmation. Isolated parallel review exists to stop that.

State: DESIGNED. Scope: The isolation mechanism is implemented as a simulation. The phantom-consensus measurement itself is unproven in the estate: 0 resolved forecasts exist to score against, so no private vs post-interaction gap has ever been measured. See blocked seam S10.

Design consequence: Review runs in isolation first, then deliberation, then a Chair. Private verdicts are logged before any interaction so the private vs post-interaction gap can be measured. Agreement is composed by dependence-aware pooling weighted by per-agent Brier scores, never by majority vote.

T5. Need explicit authority

AI generates, founder authorizes, system executes (G-1). Agents do not self-authorize. Every proposed action carries who authorized it, the scope, the expiry and a single-use token.

State: PROVEN. Scope: Proven in real test code (91/91, including 29/29 authority and gate checks). Live enforcement against a real repo host is not built; credential provisioning is BLOCKED (seam S1).

Design consequence: No packet reaches review without a valid authority header. The gate is deterministic and independent of the scoring function. A merge is an external action, so it always needs founder approval; the system prepares the packet, it cannot send it.

T6. Produce unverified claims unless gated

Agents state claims as fact. Nothing promotes on a claim alone. Promotion needs a passing gate plus a real external signal, and provisional machine decisions stay provisional.

State: PROVEN. Scope: Proven that the gate rejects in a real run (retardio run 3) and that ungated claims were found and corrected in the overnight audit. The canonical promotion rule is not settled: D-006 records two demos with different rules, so the rule itself is a blocked seam (S9).

Design consequence: The eta gate, the CRUCIBLE verdict and the promotion gate sit in the promotion path, not beside it. A failed gate blocks promotion by default. Every gate decision is receipted, including rejections.

T7. Need dedup

Recursion without dedup re-issues the same work. A loop that cannot tell new from seen will flood the review queue with repeats.

State: PROVEN. Scope: Proven in the real Retardio loop across 6 runs. Not yet proven in a review queue; no real pull request volume has run through this dedup.

Design consequence: Every packet and every observation is deduped by content hash (observation_id is SHA-256 of canonical payload) against persistent state before review starts. A repeat packet is a no-op with a receipt, not a second review.

T8. Stateless sessions, stateful system

The agent session holds nothing durable. All durable state lives in the receipt chain and the state file the loop reads and continues.

State: PROVEN. Scope: Proven in the real loop: 6 runs continued from shared state, chain head advanced, verifier reports CHAIN VALID. The source-control application of this pattern is IMPLEMENTED in the demo only.

Design consequence: State is a file plus a chain, never a session. A new agent session starts by reading the chain head and the state file. If the chain does not verify, the session does not proceed.

T9. Human traits in the loop

The founder is the source of intent and consequential authority. The human is the authorizer and exception handler, not the typist.

State: PROVEN. Scope: Proven that the gate enforces human approval in real test code (91/91). The production exception-handler workflow for source control is DESIGNED, not yet run, because no live promotion service exists (seam S6).

Design consequence: The human appears at exactly three points: intent (the mission), authorization (the gate), and exception (escalation, quarantine override, rollback decision). Everything between those points is machine work with receipts.

5. Deterministic contracts: exactly 11, one per stage

Each contract has four parts: input schema, decision rule, output schema, and failure behavior (fail-closed). Where a rule has no fixed number on record, the value is marked UNDEFINED, not filled in.

Contract 1: Compose packet

Nodes: packet-composer, agent-worker. Unified chain: Unified chain stage 1, Claim ingest. Blocked seams: none.

Input schema:

  • author_agent (string): Demo field worker-7 in the phase 1 demo receipts; no real worker fleet is wired to this system.
  • diff_summary (string): Pasted text in the demo. No real diff engine exists, so this is not a real diff.
  • files_changed (array of string): File paths named in the packet.
  • claims (array of object {claim_text: string, source: string}): Each claim must carry a source. An empty source counts as uncited at stage 6.
  • evidence (array of object): Evidence attached to claims, in the packet.

Decision rule: Dedup first, by content hash. observation_id in the real loop is SHA-256 of the canonical payload only (~/workspace/onchain-anchor/observation.py). A repeat packet is a no-op with a receipt, not a second review. Dedup is PROVEN in the Retardio loop (run 2 fetched 25, 0 new, 0 new forecasts) and NOT proven in a review queue. No packet-size, claim-count, or file-count limit is on record, so those limits are UNDEFINED. Contract check (convergence item 94, ~/workspace/convergence-100/contract.py check_message): reject unknown module, unaccepted message type, missing payload field, or missing authority where required.

Output schema:

  • packet_id (string): SHA-256 of the canonical packet payload.
  • diff (string): Pasted diff summary, as supplied.
  • ncell_header (object, 8 bytes): Stamped at stage 2, carried in the packet from here on.
  • claims (array of object): Claim set with sources, as supplied.
  • evidence (array of object): Evidence, as supplied.

Failure behavior (fail closed): Fail closed. Empty diff, empty claim set, or a failed contract check stops the walk here. No packet_id is issued. A v1.1 gate receipt is written (action gate, decision REJECTED, payload holds stage 1, reason, and input hash, not a fabricated packet). The operator sees: packet rejected at compose, reason named, no review started.

Contract 2: Stamp authority

Nodes: change-packet, ncell-authority. Unified chain: Unified chain stage 2, N-Cell/64 header stamp. Blocked seams: none.

Input schema:

  • change_packet (object): Output of stage 1.
  • authorizer (string): Who authorizes. Human approval is mandatory for any action that leaves the system (six-layer spec Layer 3).
  • scope (string): Non-empty. Empty scope is a DENY.
  • expiry (string, ISO 8601 date): Must be in the future. Expired header is a DENY.
  • token (string, 256-bit single-use token, hex): Single use. Reuse is a DENY. Revoked token is a DENY.

Decision rule: Stamp the N-Cell/64 header: 8 bytes in order routeMask, organMask, lifecycleMask, authorityMask, memoryMask, confidence, risk, outputMask (~/workspace/unified-chain/unified-chain.js stampHeader). Defaults in that file are confidence 128, organMask 0x07, every other byte 0. The worked example in that file is routeMask 0x1f, organMask 0x07, lifecycleMask 0x01, authorityMask 0x07, memoryMask 0x0f, confidence 165, risk 45, outputMask 0x01, hex 1F 07 01 07 0F A5 2D 01. The phase 1 demo derives confidence from eta and risk from blast-radius words in the diff summary; that derivation is demo-specific, not canonical. Rule: no header, no review. Header present and valid is ALLOW to stage 3; missing or invalid header is DENY.

Output schema:

  • header_bytes (array of 8 integers 0-255): In byte order above.
  • header_hex (string): Uppercase hex, space separated, for example 1F 07 01 07 0F A5 2D 01.
  • stamped_packet (object): Stage 1 packet plus header_bytes and header_hex.

Failure behavior (fail closed): Fail closed. Missing authorizer, empty scope, expired expiry, empty token, token reuse, or revoked token gives DENY. A v1.1 gate receipt is written (action gate, decision DENIED, payload holds stage 2 and the exact failing check). The walk stops. The operator sees: authorization denied, failing check named, packet does not enter review.

Contract 3: Authorize and intersect

Nodes: ncell-authority, identity. Unified chain: Unified chain stage 3, Governance intersection. Blocked seams: S1.

Input schema:

  • stamped_packet (object): Output of stage 2.
  • proposed (array of integer edge ids): E_proposed.
  • allowed (array of integer edge ids): E_allowed.
  • available (array of integer edge ids): E_available.

Decision rule: Governance intersection from ~/workspace/unified-chain/unified-chain.js governanceIntersection: E* equals E_proposed intersect E_allowed intersect E_available. Verdicts, exact: NO PROPOSAL when proposed is empty; BLOCKED when the intersection is empty; PARTIAL when the intersection is non-empty but smaller than proposed; PROCEED only when the intersection equals proposed. Default sets in that file (decision D-001, provisional): propose 8 edges, allow 6, available 5, intersection 5, verdict PARTIAL, which blocks promotion. Identity is BLOCKED (seam S1, edges E04 and E05 BLOCKED): no live identity provider is wired in, so in the demo this stage runs on the header alone. Header-only authorization is NOT proven identity. That is a gap, not a pass.

Output schema:

  • intersection (array of integer edge ids): E*, sorted, unique.
  • blocked_policy (array of integer edge ids): Proposed edges missing from E_allowed.
  • blocked_infra (array of integer edge ids): Proposed edges allowed but missing from E_available.
  • counts (object {proposed, allowed, available, intersection, blockedPolicy, blockedInfra: integer}): Counts from intersectionDetail in unified-chain.js.
  • verdict (string, one of NO PROPOSAL, BLOCKED, PARTIAL, PROCEED): Exact verdict.

Failure behavior (fail closed): Fail closed. NO PROPOSAL, BLOCKED, or PARTIAL stops the walk. A v1.1 gate receipt is written (action gate, decision DENIED or STOPPED, payload holds stage 3, verdict, blocked_policy, blocked_infra). The operator sees: intersection verdict named, blocked edges listed by id, packet does not enter review. Identity BLOCKED is also recorded on the receipt, so a header-only pass is never presented as identity-verified.

Input schema:

  • diff_hunks (array of object {file: string, function: string, blast_radius: string}): BLOCKED. Diff Engine does not exist (seam S2). In the demo reviewers read the pasted packet only.
  • ci_signals (object {tests, lint, type_check, security_scan}): BLOCKED. CI Runner does not exist (seam S3). No test, lint, type-check, or security-scan result is produced. The eta inputs that CI would feed are entered by hand in the demo.

Decision rule: Seven lenses read only the packet, in isolation: Hawkins Correctness, Orwell Security, Keystone Test Coverage, Advocate Blast Radius, Cicero Style/Consistency, Zeitgeist Documentation, Empath Risk. No agent reads another agent output. Confidence is seeded by a deterministic hash of the packet text plus the lens name (topology-data.json, T4 evidence). Per-lens verdict enum values are NOT on record, so they are UNDEFINED here; do not invent them. The debate limit is a short challenge round (Grok advice in the daybreak map); no round count is on record, so the count is UNDEFINED. Output schema:

Failure behavior (fail closed): Fail closed. A failed contract check, a missing packet, or a lens that cannot run stops the walk. If diff hunks or CI signals are absent, the walk does NOT claim a full review: the verdict is labeled SIMULATION, pasted-packet only, and the missing inputs are named on the receipt.

Contract 5: Deliberation and Chair

Nodes: deliberation-matrix, chair. Unified chain: No unified chain match. New stage.. Blocked seams: S10.

Input schema:

  • private_verdicts (array of 7 objects): Output of stage 4, already logged to the Receipt Chain.
  • challenge_log (array of object): Built in this stage, conflicting claims only.

Decision rule: Deliberation challenges only conflicting claims, per the debate limit. The Chair then produces one adjudicated outcome. Agreement is composed by dependence-aware pooling weighted by per-agent Brier scores, never by majority vote (T4 design consequence). Per-agent Brier weights cannot be computed in the estate today: 0 resolved forecasts exist, so the weights are UNDEFINED and the pooling is DESIGNED, not PROVEN (seam S10). The adjudicated outcome enum values are NOT on record, so they are UNDEFINED here.

Output schema:

  • challenge_log (array of object {claim_text: string, challenged_by: string, resolution: string}): Conflicting claims only.
  • adjudicated_outcome (object {outcome: UNDEFINED enum, claims_upheld: array, claims_rejected: array}): One outcome from the Chair.

Failure behavior (fail closed): Fail closed. If the seven private verdicts are missing, or were not logged before deliberation, the Chair does not adjudicate. A v1.1 gate receipt is written (action gate, decision STOPPED, payload holds stage 5 and the missing input). The operator sees: deliberation stopped, private verdicts missing or unlogged, no adjudicated outcome. The walk does not proceed to CRUCIBLE on an unlogged review.

Contract 6: CRUCIBLE verdict

Nodes: crucible, sentinel-court. Unified chain: Unified chain stage 5, CRUCIBLE verdict. Blocked seams: none.

Input schema:

  • adjudicated_outcome (object): Output of stage 5.
  • claims (array of object {claim_text: string, source: string}): Claims with sources.
  • I_q (number 0-100): Quality.
  • I_r (number 0-100): Relevance.
  • I_v (number 0-100): Verification.
  • E_wasted (number 0-10): Wasted effort.
  • C_violations (number 0-10): Constraint violations.
  • feedback_accuracy (number): Used only by etaGate in unified-chain.js; seed_allowed needs 0.6 or above. No feedback accuracy value is recorded for source control review, so it is UNDEFINED for this stage unless a caller supplies one.

Decision rule: Eta formula, exact: eta equals (I_q times I_r times I_v) divided by (1 plus E_wasted plus C_violations), clamped to 0-100, threshold 70. PASS needs eta at or above 70 AND uncited count zero, where uncited count is the number of claims with an empty source field. Prefill fact, verified: inputs I_q 88, I_r 90, I_v 85, E_wasted 1, C_violations 0 give raw 336600, clamped to 100, not 78. The demo pages show raw and capped. CRUCIBLE score bands in unified-chain.js crucibleVerdict are separate and also apply where that function is used: score equals max(0, emergence_raw minus objection_penalty) times signal multiplier (contract 1.00, pilot 0.50, lead 0.30, none 0.15); KILL below 20, ITERATE 20-49, SHIP-CANDIDATE at or above 50 only with a real external signal, else ITERATE. EtaGate seed_allowed needs eta at or above 70 AND feedback_accuracy at or above 0.6. Sentinel Court is the independent check on the verdict (edges E26, E27, SIMULATED); no independent verifier service exists, so its confirm or veto is SIMULATED, not a live second opinion.

Output schema:

  • eta_raw (number): Unclamped (I_q times I_r times I_v) divided by (1 plus E_wasted plus C_violations).
  • eta (number 0-100): eta_raw clamped to 0-100, rounded to 2 decimals.
  • uncited_count (integer): Claims with an empty source field.
  • uncited_claims (array of string): Exact text of each uncited claim.
  • verdict (string, PASS or FLAG): PASS only when eta at or above 70 AND uncited_count is 0.
