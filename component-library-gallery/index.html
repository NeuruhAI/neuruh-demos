01 · Overview

Source claim: 59 .tsx files were found in the working set. 25 components are re-implemented live in this gallery. The rest are listed in the Honest gaps section with reasons.

Required note. Everything on this page is a re-implementation of the .tsx components for the browser in vanilla JavaScript and CSS. This is not the React code itself. There is no React runtime, no Radix, no Recharts, no Tailwind, and no @/lib/utils here. Behavior was matched to the source props and variants; the styling follows the editorial document standard of this page, not the original dark glass theme of the organism components.

Share this state

The current gallery state (active section, chart data, form values, table sort) is encoded into the URL hash as base64 JSON. Open the link on any machine and the gallery restores itself.

What is on this page

Use the sidebar to switch sections. Every section renders the component live: click it, type in it, sort it, break it. Three sample compositions combine components the way a real screen would: a dashboard (StatCard + chart + ActivityFeed), a validated form, and a sortable data table.

09 · Try-it Walkthrough

Seven steps, each one a real interaction. Work through them in order; each step names the component and the exact thing to try.

  1. Switch sections with the sidebar. Click any sidebar item; the main view changes and the item highlights. The sidebar is itself a re-implementation of sidebar.tsx.
  2. Click a button. In Buttons, click any variant and watch the click counter and last-clicked label update.
  3. Open a dialog, then cancel it. In Overlays, open the dialog, close it with the X, then open the alert dialog and choose Cancel. Read the outcome text after each.
  4. Break the form, then fix it. In Forms, submit with everything empty and read the four errors. Fill in a name and a bad email and submit again; only the email error should remain. Fix the email, pick a role, accept the terms, and submit: the completeness meter reaches 4 of 4.
  5. Sort the table twice. In Data Display, click the Agents header to sort ascending, then click again to sort descending. The row order must reverse exactly.
  6. Change the chart data. In Data Display, edit the JSON in the chart editor (for example change the Apr value from 80 to 20) and click Apply. The tallest bar must change and the stats line must update.
  7. Share the state. Use the Copy link button in the Overview, open the link in a new tab, and confirm the chart data, form values, and active section come back.

10 · How it works / What this is not

How it works

  • One HTML file. All CSS is in a <style> block, all behavior in one <script> block. No external dependencies, no CDN, no images, no network fetches.
  • State lives in a plain JavaScript object: active section, chart data, form values, table sort key and direction, pagination page, calendar month and year.
  • The chart is drawn as inline SVG. Bar heights are computed as value / max * chartHeight. The area line is a polyline through the same scaled points.
  • The calendar grid is computed with the Date API: first day of the month, days in the month, and leading blank cells. Nothing about any month is hard-coded.
  • Share state is #d= followed by base64 of a JSON object. On load, the page parses the hash and restores the state before rendering.
  • Every control was tested in jsdom with hand-computed expected values. The test count is reported in the staging report, not on this page.

What this is not

  • Not the React code. There is no React, Radix, Recharts, Tailwind, or shadcn runtime here. These are vanilla re-implementations matched to the source props and variants.
  • Not a design-system replica. The original organism components use a dark glass theme with cyan and purple gradients; this page uses the light editorial document standard, so colors and surfaces differ on purpose.
  • Not a data source. All data on this page is sample data written for the demo. Nothing is fetched, and nothing is persisted except the share link you copy.
  • Not accessible to the same standard as Radix. Keyboard support is partial: tabs, switches, and sliders use native semantics, but the custom select, popover, and dropdown are click-driven and have limited keyboard handling. This is listed as a gap below.
  • Not deployed. This file is staged only. Nothing on this page is live on any domain.

Files NOT re-implemented, and why

  • carousel.tsx: needs swipe and scroll-snap behavior; a static strip would misrepresent it. Omitted rather than faked.
  • command.tsx: a command palette with fuzzy search; out of scope for a component gallery and needs a keyboard-first interaction model the page does not fully support.
  • context-menu.tsx: right-click menu; the gallery has no canvas to right-click on, so it would be a demo of nothing.
  • drawer.tsx and sheet.tsx: slide-over panels. The dialog covers the modal pattern; a second slide-over adds little and the sidebar already demonstrates the off-canvas idea.
  • hover-card.tsx: hover-triggered card. Tooltip covers the hover pattern; omitted to keep the page focused.
  • menubar.tsx and navigation-menu.tsx: application menu bars. The sidebar navigation covers navigation; a second menu bar would duplicate it.
  • collapsible.tsx: covered in behavior by the accordion; the standalone collapsible adds no new interaction.
  • resizable.tsx: drag-to-resize panels. Needs pointer-drag handling that is hard to verify deterministically in jsdom; omitted rather than half-built.
  • input-otp.tsx: six-slot one-time-code input. Not re-implemented; the form section covers text input and the OTP pattern needs a real code flow to be meaningful.
  • input-group.tsx: input addons and buttons. The form section covers the same controls without the addon chrome.
  • item.tsx: list item layout primitive. The feed rows and agent list already demonstrate the pattern.
  • empty.tsx: empty-state layout. Static layout with no interaction; noted here instead of a dedicated card.
  • aspect-ratio.tsx: a ratio box. Pure CSS layout with no behavior; not a gallery-worthy demo.
  • USMap.tsx: an interactive United States map with agent markers and click handling. Needs real map geometry; a fake outline would misrepresent the component. Omitted.
  • toggle-group.tsx: covered in behavior by the button group and the toggle; the group variant adds no new interaction.
  • scroll-area.tsx: custom scrollbar primitive. Behavior only; the feed uses a native scroll region and this is noted in the mapping.

Duplication and gaps found in the sources

  • Two chart implementations overlap: chart.tsx is a generic Recharts wrapper with a ChartConfig, while PerformanceChart.tsx is a separate area-chart component with its own tooltip and gradient. They are not the same abstraction; the gallery merges them into one SVG chart and says so.
  • LegionCard.tsx imports Button, Progress, ScrollArea, and LegionIcon3D, so it is a composition, not a primitive. The gallery treats it as one.
  • sidebar.tsx is the largest file and imports Button, Input, Separator, Sheet, Skeleton, and Tooltip. The gallery re-implements only the desktop navigation behavior; the mobile sheet, the sidebar_state cookie, and the icon-collapse mode are not reproduced.
  • StatCard.tsx and PerformanceChart.tsx hard-code a dark glass aesthetic (white text, cyan #00d4ff, purple #a855f7) that assumes a dark page. The gallery restyles them for the light editorial standard; the props and behavior are preserved, the theme is not.
  • PerformanceChart.tsx computes a max value in a useMemo and then never uses the result. Flagged as dead code in the source; the gallery computes the max and actually uses it for scaling.
  • sidebar.tsx SidebarMenuSkeleton generates a random width (50 to 90 percent) on each render. The gallery does not reproduce random widths; the skeleton demo uses fixed widths so tests are deterministic.
  • The source set has no @/lib/utils cn helper and no @/hooks/use-mobile in the working set, so those imports could not be read. Anything depending on them is marked as behavior-matched, not code-matched.

What could not be verified

  • Layout was not eyeballed in a real browser. The page was tested in jsdom for behavior only; visual layout, spacing, and the print stylesheet are unverified in a real renderer.
  • The original components were not run in React, so variant class names are matched from reading the source, not from rendered output.
  • Accessibility beyond basic roles and labels was not audited; the custom select, popover, and dropdown have limited keyboard support.
