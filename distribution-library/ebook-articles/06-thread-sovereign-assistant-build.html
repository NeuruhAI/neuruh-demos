1/ A personal executive agent is not one agent. It is an organization. One supervisor, four specialists, a memory graph, and human gates on everything consequential. Here is the build.

2/ The supervisor's job is not answering questions. It plans, delegates, and recovers from errors. A linear chain dies at "file not found." A supervisor routes to a retry node. That is the whole gap between a demo and a system.

3/ Define the supervisor's state schema before any node: messages, context, plan, current step, errors. If your state cannot represent "this step failed, here is why," your recovery logic has nowhere to live.

4/ Four workers, four boundaries. Archivist: retrieval and graph upkeep. Executive: scheduling, email, commitments. Analyst: code, always in a sandbox. Navigator: the browser, for whatever has no API. Narrow scope is the feature.

5/ Never ask the model to do math. Models predict tokens; they do not run arithmetic. The model writes the code, a sandbox runs it, and every number comes back with the script and the input hash. Receipts are how you debug reality.

6/ Memory is a graph, not a pile. Vector search finds text like your query. A graph walks relationships: who owns what, what blocks what, what you promised. "Why did the renewal slip" is a traversal, not a similarity match.

7/ Start the schema small: Person, Organization, Project, Document, Meeting, Concept. Every edge type you add is a distinction the extractor must make correctly thousands of times. Schema changes are migrations. Version it.

8/ The Executive stays read-only for two weeks. It drafts only when the summaries are consistently right. It never sends without the human gate. The gate is a node in the graph, not a prompt instruction. Injected text can argue with a prompt. It cannot argue with a halt.

9/ Where things run: anything touching your full history runs locally. Ollama, a local graph DB, local embeddings. Frontier models get the hard reasoning calls. The nightly ingest over your whole history is where cloud pricing bleeds you.

10/ Build order: graph first, then MCP servers for your top three sources, then supervisor plus one worker. Prove error recovery at small scale before anything else exists. Each step must be useful on its own.

11/ Demand receipts from your own system: logged supervisor decisions, cited sources on every answer, rerunnable scripts behind every number, a written list of gated tools. This is what separates a system from a demo.

12/ Full version is a long essay adapted from my book The Sovereign Assistant (The Neuruh Papers, book 6). If you want one built for you: cal.com/neuruh
