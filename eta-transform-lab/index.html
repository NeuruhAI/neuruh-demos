2. eta calculator with step-by-step working

Formula (sourced, pinned form): eta = (I_quality x I_relevance x I_velocity) / (1 + E_wasted + C_violations), bounded 0 to 100.

Input scales are a builder design decision (mine, see section 8): I_quality, I_relevance, I_velocity on 0 to 1, matching the dossier statement that raw eta is bounded (0,1] and scaled 0 to 100. E_wasted and C_violations are non-negative integer counts. Feedback accuracy on 0 to 1.

Presets load inputs, then run. STRONG and FABRICATED reproduce the sourced expected outputs (86.0 and 0.0); their inputs are builder choices, since the dossier states the outputs but not the inputs.

3. Seed and verification walkthrough: STRONG vs FABRICATED

Expected outputs below are transcript-quoted from the Batch 010 dossier, section 11 (test_full_loop.py). Whether the test ran green on the Mac is UNKNOWN. This page recomputes the eta and gate steps live; it does not run the Mac test.

Case A: STRONG cluster Expected eta 86.0

Preset inputs (builder choices): I_quality 0.86, I_relevance 1.00, I_velocity 1.00, E_wasted 0, C_violations 0, feedback accuracy 0.90 (accuracy is my choice; the dossier gives no accuracy for this case).

Working: (0.86 x 1.00 x 1.00) / (1 + 0 + 0) = 0.86 / 1 = 0.86, scaled x100 = 86.0. Gate: 86.0 >= 70 and 0.90 >= 0.6, so SEED.

Quoted expected outcome from the dossier: qubit saved, provenance_ok=True; seeded=True with fidelity loss_pct 0.03 and dropped fields exact_parcel_geometry and owner_phone.

Case B: FABRICATED world Expected eta 0.0, blocked

Preset inputs (builder choices): I_quality 0, I_relevance 0, I_velocity 0, E_wasted 0, C_violations 0, feedback accuracy 0.90. A fabricated world carries no real information, so every I term is zero.

Working: (0 x 0 x 0) / (1 + 0 + 0) = 0 / 1 = 0, scaled x100 = 0.0. Gate: doctrine-eta 0.0 < 70, so BLOCKED. This is the same rail that blocks the L4 amplifier forecast (current 0 to day14 94) from birthing a world on trend alone.

Quoted expected outcome from the dossier: fabricated seeded=False, gate message "doctrine-eta 0.0 < 70".

Note on the amplifier: the L4 amplifier forecast is advisory only after the 2026-11-10 Option 1 decision. It can never pass or fail a seed. This demo does not implement the amplifier; it implements the doctrine gate that replaced it as judge.

4. Codebook status: STUB

Codebook status: STUB. No real VQ codebook exists (sourced: Batch 010 dossier, section 10; MTH-023). The stub is deterministic SHA-256 hash-bucket centroids: SHA-256 of the group label, bytes to floats in [-1, 1], dim 16, mode stub-hashbucket. Same group in, same centroid out. This is not a learned codebook and not a semantic embedding. Any external artifact must carry the flag: codebook_mode = stub is not a semantic embedding yet.

Try it: type a group label and press Compute centroid. The centroid is computed for real in your browser with Web Crypto.

Each completed run emits one receipt format v1.0 record. 8. Design decisions (the builder's, not paper claims, not Jeramie's order)

  1. Input scales. I_quality, I_relevance, I_velocity on 0 to 1; E_wasted and C_violations as non-negative integer counts; feedback accuracy on 0 to 1. The dossier states raw eta is bounded (0,1] and scaled 0 to 100, and gives no input ranges; the scales above are my choice to make that scaling concrete.
  2. Preset inputs. STRONG uses (0.86, 1.00, 1.00, 0, 0) and FABRICATED uses (0, 0, 0, 0, 0). The dossier states the expected outputs (86.0, 0.0) but not the inputs; these inputs are my choice so the sourced formula reproduces the sourced outputs exactly. STRONG accuracy 0.90 is also my choice.
  3. Marginal preset. (0.80, 0.80, 0.80, 0, 0) gives eta 51.2, blocked on eta. My choice, to show a near-miss case.
  4. Rounding. eta is rounded to 1 decimal, matching the dossier's one-decimal expected values (86.0, 0.0).
  5. Stub centroid float mapping. First 16 digest bytes, float = byte / 127.5 - 1, rounded to 4 decimals. Codebook id = first 6 hex chars of the digest as an integer. The dossier states SHA-256 to bytes to floats in [-1, 1], dim 16; the byte-to-float mapping is my choice.
  6. Qubit builder defaults. loss_pct default 0.03 and dropped fields exact_parcel_geometry, owner_phone are copied from the quoted STRONG expected outcome; they are defaults for the demo form, not a claim that every qubit has that loss.
  7. Receipt ids. eta-20261114-0001 and up, per session run. This demo chain is separate from every other demo chain.
  8. Hashing. Web Crypto (crypto.subtle) in the browser, async. The Node test uses the same globalThis.crypto path and cross-checks against Node crypto.createHash.
