SECTION 05

Recipe engine and G-1 founder approval

The recipe engine protects execution of recipe logic. Its governance mechanism is founder approval, G-1.

Click one of the three

Generate, authorize, and execute are three different powers. Confusing any two is how governance gets bypassed.

The separation

AI CAN GENERATE is not AI CAN AUTHORIZE is not AI CAN EXECUTE. AI may generate a recipe, a plan, or a candidate action. Only the founder authorizes. Only a governed worker executes, and only inside the authorized boundary. Do not bypass governance to make a demo look more autonomous.

SECTION 07

The organism layer

Workers, queues, and the monitoring organs. Architecture first, then the hard rule that keeps the organism governed.

Hard rule: hunt creation must never auto-execute

A hunt is created, reviewed, and authorized before anything runs. JobQueue holds work; it does not fire it. Any path that lets creation become execution without a founder authorization is a governance break, not a feature.

Agent receipt

Every agent action leaves a receipt: who acted, what ran, under what authority, with what input and output. An agent without a receipt is an agent that cannot be audited, and an unauditable agent does not run in production.

    SECTION 19

    The paradox: AI velocity greater than human integration capacity

    Building got fast. Integrating, verifying, deploying, and operating did not get fast at the same rate. The gap between the two is where the estate's entropy lives.

    The 14 consequences

    The Sep 26 transcript enumerates 14 consequences of the paradox. The available spec does not list them, and the source transcript file was not present when this page was built, so they are not reproduced here. Do not treat the list below as that enumeration: it is the related consequence set recorded in IDENTITY.md section 19, for the same bottleneck, cross-referenced so the section is useful until the transcript lands.

    The shape of the paradox

    Velocity without integration capacity produces volume without closure. More built things, more scattered state, more decisions waiting on one person. The answer is not to slow the building. The answer is to raise integration capacity, which is what convergence means.

    SECTION 20

    The biggest mistake Muse could make

    Do not create more architecture, dashboard, agent, repo, or 40-page strategy document

    Do not send Jeramie on another archaeology expedition. Do not answer a coordination problem with a new system that needs coordinating. The phase is CONVERGENCE: recover, reconcile, repair, converge. Rebuild only when the existing system is proven unrecoverable.

    Every new component creates state, dependencies, maintenance, security surface, documentation burden, deployment burden, and cognitive load. New architecture must earn its existence. Before creating anything new, ask: does this capability already exist, where is its canonical implementation, and is the existing implementation broken, incomplete, obsolete, or merely undiscovered?
