Section 2 · Operating model

The ten organism layers

The model separates core intelligence infrastructure from domain applications, so no product ships its own user table, data layer, prompt logic, reporting format, and half-baked memory system. Select a layer to see its responsibility and how it shows up in two different products.

Core rule: one organism, many organs. A product may own a UI and a domain workflow, but it must not own a separate memory layer, evidence layer, governance layer, or report engine. Every new product answers four questions: which contracts does it use, which organs does it call, which events does it emit, and which governance policies control it?

Section 3 · APG Land CRM on the organism

One deal, intake to receipt

APG Land CRM is the real-estate cockpit, not the brain. It captures leads and displays deal state; the heavy intelligence lives beneath it in the organs. Step through a single deal's path.

What the CRM must never do

  • Silently change ARV, MAO, repair math, or market velocity formulas.
  • Generate seller-facing offers without governance approval.
  • Store unsupported facts as truth. Facts are stored as claims with an evidence status.
  • Resolve zoning, title, legal, or tax conflicts without a human review path.
  • Become a second organism. The CRM is the cockpit. The organism is the machine.

N-Cell position paper · Governed Adaptive Topology Protocol

N-Cell: one byte of local topology

At any moment the organism is a directed, attributed graph: G_t = (V, E_t, X_t, P_t), the registry, the active topology, the state, and the governance constraints. Each node carries an eight-bit routing mask over its Moore neighborhood. Toggle the neighbors of node v to build its route mask.

R_v(t) = Σi=0..7 b_i(t) · 2i,  b_i ∈ {0,1}  →  256 local activation patterns

The eight bits may represent spatial directions, logical neighbor classes, event channels, or registered capability edges. The mapping must be declared in a versioned schema. A practical organism uses multiple masks rather than forcing all meaning into one byte, which is what the N-Cell/64 header does:

BYTE 0routeMask

Permitted local event routes or neighbor relationships.

BYTE 1organMask

Active specialist organs or capability families.

BYTE 2lifecycleMask

Workflow stage and completion state.

BYTE 3authorityMask

Observe, recommend, draft, stage, execute, emergency block.

BYTE 4memoryMask

Permitted working, episodic, semantic, procedural, prospective, founder, and outcome planes.

BYTE 5confidence

Quantized evidence or decision confidence, 0–255.

BYTE 6risk

Quantized escalation or hazard score, 0–255.

BYTE 7outputMask

Permitted artifacts, messages, APIs, physical commands, or World emission state.

E*_t = E_proposed(t) ∩ E_allowed(t) ∩ E_available(t)

Topology receipts: ΔG_t = G_t ⊕ G_(t−1). XOR flags what changed; the receipt still carries the semantic evidence: why a route changed, which policy acted, which model proposed the change, and what outcome followed. N-Cell is a compact signature and observability layer on the existing organism, not a replacement architecture and not a substitute for the Vault.

Codex V2 · The modulated agentic system

Twelve runtime variables, one fixed identity

A conventional multi-agent system assigns fixed roles and fixed workflows. Neuruh modulates all twelve of these variables per opportunity, while identity, contracts, memory, evidence requirements, governance, and operating doctrine stay fixed.

Environment

Where the run executes and what infrastructure is actually available.

Opportunity type

The class of value being pursued: transition, land, business, asset, IP.

Agent role

Which registered agents compose the temporary topology.

Model

Which model serves which node, routed by task and cost.

Memory scope

Which Vault planes a node may read, and nothing beyond them.

Tool access

Which tools and adapters are bound to the run.

Collaboration topology

How nodes communicate: the N-Cell graph for this run.

Authority

Observe → recommend → draft → stage → execute → emergency block.

Risk threshold

How much hazard a run may carry before it must escalate.

Economics

Budget, cost envelope, and expected value of the opportunity.

Output contract

Which artifacts the run may emit, and to whom.

Evaluation standard

The harness and thresholds the result is scored against.

The core systems problem: given an objective, an environment, available capabilities, and policy constraints, select and execute the smallest sufficient topology of agents, tools, models, memories, deterministic organs, and human approvals that maximizes expected outcome quality while minimizing cost, latency, risk, and unsupported claims. Fixed orchestration fails because the same team is overbuilt for simple work, underbuilt for complex work, and cannot respond cleanly to missing evidence, tool failure, or changed risk.

Section 10 · Immune system

Governance and the kill-switch

The immune system protects the organism from unsupported conclusions, legal risk, financial overreach, and operational chaos. Policy-driven and auditable: every policy area defines what is blocked automatically, what escalates to a human, and what proceeds with a visible warning.

Policy areaAutomatic blockEscalationAllowed with warning
Evidence sufficiency BlockARV report with fewer than three acceptable comps and no documented fallback. EscalateSparse data but a transparent confidence score. WarnThree comps present, confidence below target.
Seller-facing offers BlockOwnership unverified or seller authority unclear. EscalateConflicting seller notes or title flags. WarnVerified seller, approved offer, sufficient confidence.
Creative finance BlockNo loan details, arrears, or seller-consent path. EscalateDue-on-sale or legal structure unclear. WarnTerms modeled with an attorney-review flag.
Zoning and development BlockBuildability claim without zoning or source evidence. EscalateAmbiguous ordinance or conflicting GIS layers. WarnConceptual HBU marked non-binding.
Tax and legal BlockDirect legal or tax conclusion without professional review. EscalateEntity, lien, probate, or tax exposure involved. WarnEducational estimate with disclaimer and review path.
Data licensing BlockRestricted provider data used in a public report. EscalateReuse rights unclear. WarnInternal-only source properly marked.

The emitter rule

  • Reports can summarize evidence. They cannot create evidence.
  • Seller-facing outputs require governance approval, every time.
  • Any unsupported assumption is labeled as an assumption or excluded.

Anti-patterns, blocked by design

  • Standalone code recreating identity, evidence, memory, governance, or reporting.
  • LLM-written dollar values that bypass deterministic formulas.
  • Comp selection with no rejected-comp audit trail.
  • Zoning conclusions with no ordinance or GIS evidence.
  • Outcome learning that changes behavior without versioned policy approval.
  • A CRM treated as the source of truth for facts it merely displayed.

Risk categories under watch: title, lien, probate, ownership, authority, tax delinquency, foreclosure, and redemption; zoning, land-use, floodplain, wetland, environmental, utility, access, and easement; structural, roof, foundation, mechanical, occupancy, tenant, code, and permit; market liquidity, rental demand, investor appetite, buyer financeability, and disposition; data quality, conflicting facts, stale evidence, missing comps, and low-confidence model output.

Section 9 · Memory, learning, and the Vault

Six memory types, one governed learning loop

The Vault is not a flat chat log. It holds typed memory with permissions, decay rules, and an outcome calibration loop, so the organism develops continuity instead of amnesia.

Episodic

Specific runs and deal histories.

“The 935 S 28th St underwriting run and its final disposition.”

Semantic

Durable knowledge and market facts.

“River Park 2/1 homes lease within a supported band, given the data.”

Procedural

How to perform a workflow.

“The residential ARV comp-selection relaxation order.”

Prospective

Future follow-ups and pending actions.

“Re-check the inspection report when the seller uploads it.”

Priority State

Current active objectives.

“Build Real Estate Organ Pack V1 integration.”

User / Brand Preference

Stable preferences and templates.

“APG visual language, report formatting, acquisition thresholds.”

The outcome learning loop

1

Store the original prediction with its formulas, assumptions, evidence, and model version.

2

Record the actual outcome: purchase price, repair cost, resale or rent, DOM, profit, timeline.

3

Calculate the variance between predicted and actual values.

4

Tag the variance source: bad evidence, market shift, repair miss, comp mistake, or execution issue.

5

Calibrate only through governed rule updates. Never silent prompt drift.

N-Cell paper · Prior art and novelty boundaries

What is proven, what is synthesis, what is hypothesis

The paper's own discipline, applied to itself: the architecture is real enough to formalize and test, not yet proven enough to market as AGI. Microsoft, OpenAI, Anthropic, LangChain, Palantir, ServiceNow, Salesforce, and the dynamic-topology research line already cover many of the primitives. The defensible ground is the integration.

EstablishedSubstantial prior art exists. Language: “uses” or “implements,” never “invented.”

ValidatedA controlled benchmark supports the claim, with metrics and limitations reported.
ReplicatedAn independent party reproduces the result from a named package.

Eight falsifiable hypotheses

H1

Task-adaptive topology improves success versus the best fixed topology, using identical models and tools.

H2

N-Cell state signatures reduce debugging and incident-resolution time without losing semantic traceability.

H3

Governance graph reduction lowers the unauthorized-action rate while preserving useful completion.

H4

Outcome-linked memory changes future topology selection in a direction that improves calibration.

H5

Sparse route activation reduces token and latency cost at equal or better quality than dense communication.

H6

One canonical substrate transfers across at least five Worlds with limited domain-specific orchestration code.

H7

Topology receipts improve reproducibility of stochastic agent runs.

H8

Opportunity-centered composition produces higher measurable economic value than task-centered automation alone.
