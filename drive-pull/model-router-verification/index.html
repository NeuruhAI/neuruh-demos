AXON Model Router Verification

VERIFIED. Contents API returns sha 51ee3480f109680ec3896ced65fb629b4387be35, exact match to the claimed SHA.

Claim 3: Five routing strategies (cost, speed, quality, local-first, fallback-chain)

VERIFIED. Line 4:

export type RoutingStrategy = 'cost' | 'speed' | 'quality' | 'local-first' | 'fallback-chain';

Each has an implementation: routeByCost (line 97), routeBySpeed (line 108), routeByQuality (line 116), routeLocalFirst (line 125), routeByFallbackChain (line 131).

Claim 4: Adapter registration and health checks

VERIFIED. registerAdapter (line 42) and removeAdapter (line 48) manage the adapter map. Health checks: getHealthyCandidates (line 136) calls adapter.isHealthy() (line 141) and skips unhealthy adapters. selectAdapter also checks isHealthy() before honoring a forced provider (line 57).

Claim 5: Capability and cost filtering

VERIFIED. getHealthyCandidates filters on rule.requiredCapabilities (streaming, tool-calls, lines 144-146), rule.maxCostPer1k (lines 148-150), and rule.preferLocal (line 151).

Claim 6: Automatic fallback when a provider fails

VERIFIED. route() (line 80) iterates the fallback-ordered candidates, tries adapter.generate(request), counts the request, and on error or a response with an error field continues to the next adapter (lines 84-93). It throws only after all adapters fail (line 94).

Claim 7: Per-provider request and error statistics

VERIFIED. requestCounts and errorCounts maps (lines 35-36), incremented in route() (lines 86, 90), exposed by getStats() (line 166) returning requests, errors, and errorRate per provider.

Claim 8: Adapter contract in src/adapters/adapter-interface.ts

VERIFIED. File exists on main, size 1,053 bytes, blob SHA 5efa3161b6fb405add062a75c55f64640833a06d. Defines ModelInfo, AdapterMessage, AdapterRequest, AdapterResponse, and AdapterInterface (provider, getModelInfo, isHealthy, generate, optional stream).

Claim 9: RoutingRule defines taskType but selection code does not use it

VERIFIED. taskType?: string; appears exactly once in the 177-line file, at line 7 inside the RoutingRule interface (grep count: 1). No line in selectAdapter, route, getHealthyCandidates, or any strategy method reads rule.taskType. The only RoutingRule fields ever read are provider (line 55), requiredCapabilities (lines 144-146), maxCostPer1k (line 148), and preferLocal (line 151).

Claim 10: route() orders by fallback chain rather than applying the selected strategy

VERIFIED. route() (lines 80-95) calls getHealthyCandidates, then orderByFallback (line 82), then iterates that order. It never calls selectAdapter or any strategy method. The strategy switch exists only in selectAdapter (lines 65-77), which is a separate entry point. Nuance: the default strategy is 'fallback-chain' (line 27), so under the default config route() and selectAdapter agree. The divergence appears only when a non-default strategy is configured: route() still uses fallback order.

Claim 11: inference-mesh-router is archived and separate

VERIFIED. NeuruhAI/inference-mesh-router exists, private, default branch main, archived: true, last pushed 2026-07-30T03:26:11Z. It is a separate repo from neuruh-axon.
