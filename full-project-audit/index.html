7Supabase RLS security finding: technical debt, not an emergency

The audit found real issues in the Supabase layer. Present them as technical debt to schedule, not as a breach or an emergency. Click each finding for the detail.

Overlapping permissive policies HANGING

Row-level security policies overlap permissively, so more than one policy can grant the same access. The effect is wider access than intended, not an open door. Fix by consolidating policies so each table has one clear permissive path, then re-testing access per role.

Duplicate indexes on market_research HANGING

Duplicate indexes on the market_research table waste write time and storage and confuse query planning. Fix by dropping the redundant index after confirming which one the live queries actually use.

Auth connection allocation advisory HANGING

An advisory on Auth connection allocation: connection usage should be reviewed against the pool before it becomes a limit under load. Fix by measuring peak Auth connections, then sizing the pool or the retry behavior to match.

Finding order: policies first (access correctness), indexes second (performance), connection allocation third (capacity). None of the three is an emergency. All three are debt that compounds if ignored.

9The commercial bottleneck: interactive flow

The system builds, audits, courts, improves, and canonizes. That loop is real and it works. What does not exist is the transition from PROVEN to SOLD to DELIVERED to OUTCOME to CASE to LEARNING. Toggle between the two flows and click any stage.

Select a stage in either flow. The bottleneck in one line: the build loop is closed, the commercial loop is open.

The bottleneck, stated plainly HANGING

Every stage of the build loop has receipts. No stage of the commercial transition does, because the transition has not been run. The next mission is not another build. It is one sale, one delivery, one outcome, one case, and the learning that follows. That is the missing transition, run once.

12Local custody risk

The working state at the cut is dirty and divergent. NEURUH-HD is cold custody only: it holds copies, it does not hold the live truth.

neuruh-runtime-custody: 119 dirty files HANGING

119 dirty files in neuruh-runtime-custody at the cut. Dirty means changed and uncommitted. Uncommitted work is work that can be lost, overwritten, or misread as done.

88-file WIP HANGING

An 88-file work in progress, uncommitted at the cut. A WIP that large is not a change, it is a branch of its own, and it needs to be split, committed, or discarded before it rots.

Vault: 73 ahead / 5 behind HANGING

The Vault is 73 commits ahead and 5 behind at the cut. Ahead and behind at once means divergent histories that need a merge or a rebase decision, not another commit on top.

Multiple worktrees HANGING

Multiple worktrees spread the same work across several checked-out copies. Each worktree is a place where state can drift from the others. The count itself is the risk: one truth, many copies, no single reconciliation point.

NEURUH-HD is cold custody only. It is the archive drive, not the working drive. Treat it as the copy you restore from, never as the place where live work happens.

Triage hidden.

  1. Commit or discard the 119 dirty files, file by file, nothing in bulk.
  2. Split the 88-file WIP into reviewable commits or park it as a named branch.
  3. Resolve Vault 73 ahead / 5 behind with an explicit merge decision.
  4. Reconcile worktrees to one working copy and archive the rest.
  5. Verify NEURUH-HD cold copy matches the sealed state, then leave it cold.
