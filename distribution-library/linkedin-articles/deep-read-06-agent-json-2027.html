In 2027 Your Website Will Need an agent.json

In 1997 your website needed a robots.txt. In 2027 it will need an agent.json.

That is not a slogan. It is a prediction with a date on it, from a paper I wrote on building a personal sovereign agent. The argument: websites will publish agent manifests, similar to robots.txt but for agents, telling visiting AI systems what they are allowed to do, which tools they can touch, and under what authority. The web is about to become a place where agents negotiate with agents. Your site will need a front door for them, the way it once needed a front door for crawlers.

I am putting that call on the record because of what it implies about what to build right now.

The machine that clicks

The paper is a build blueprint for what it calls Project Mnemosyne: a personal executive agent that is a digital entity, not a chatbot with a function-calling garnish. The supervisor is a deterministic engine, cyclic error recovery, time travel on state, chosen because it is controllable. The clever sub-systems, the planners and the crews, live inside it as encapsulated sub-graphs. The deterministic layer stays in charge.

This is the same separation-of-powers instinct that runs through everything I build. The part that decides is not the part that performs. The part that performs is not the part that verifies. When the agent needs to touch your real life, the paper specifies a zero-trust posture: OAuth device flows, least privilege, human-in-the-loop interrupts at the dangerous edges. The browser automation is not "the agent that helps." It is "the agent that clicks," and the paper treats that as a capability that needs a leash, not a feature that needs marketing.

USB-C for AI

The connective tissue in the blueprint is MCP, which the paper calls "the USB-C for AI": one standard connector for Drive, Notion, Slack, chats, all of it. The memory layer is a personal knowledge graph, and the paper is specific about the stack: GraphRAG over a knowledge graph with KuzuDB, which it calls "the DuckDB of Graphs," embedded, fast to ingest, plus a vector store. ETL through unstructured extraction and graph transformers. Sandboxed code execution.

Here is the part that sold me on my own paper. Vector search finds text chunks that are similar to your query. GraphRAG finds the thing the chunks are about. Ask "how is the team feeling about the timeline" and vector search hands you every document with the word timeline in it. GraphRAG does community detection on the relationships between people, projects, and dates, and answers the actual question. Similarity is not understanding. Relationships are understanding.

The paper closes with the honest line that should be on every AI blueprint: the challenge is no longer scientific discovery. It is systems integration.

Build for the negotiating web

So the prediction again, with the mechanism: agent.json manifests, robots.txt for agents, arriving around 2027, on a web where agents negotiate with agents. Prediction, date, mechanism. If it lands, the people who built deterministic supervisors, real memory graphs, and zero-trust tool access will already be standing where the web is going. If it does not land on schedule, they still built systems that are controllable, auditable, and useful in the web we have.

That is how I like my predictions: dated, falsifiable, and attached to work that is worth doing either way.

Start treating your website like it has two audiences. The humans who read it and the agents that will soon be negotiating with it. The ones who prepare the second front door now will not be surprised when the knocking starts.
