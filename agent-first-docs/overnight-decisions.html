Overnight Decisions Log, 2026-11-14

Every design conclusion formed by the overnight coordinator (not a paper claim, not Jeramie's order). Format: gap, decision, rationale, what would change it.

D-001, Governance Loop defaults (2026-11-14 ~01:21 EST, builder decision, recorded by coordinator)

  • Gap: N-Cell paper §3.3 defines the 8-byte header layout but sets no numeric defaults; the N-Cell adapter demo shows the intersection formula but does not compute it.
  • Decision: defaults confidence 128, all other bytes 0, organMask 0x07 from SAL manifest bits 0-2; default header 00 07 00 00 00 80 00 00. Default intersection (propose 8, allow 6, available 5) yields PARTIAL, which blocks promotion. The passing preset proposes 4 edges inside allowed/available to reach PROCEED.
  • Rationale: neutral midpoint confidence; SAL is the proposing organ so its bits are the natural default; PARTIAL as the default makes blocking behavior visible immediately instead of silently passing.
  • What would change it: paper-defined defaults, or an Organ Manifest that assigns route/authority defaults.

D-002, Receipt-Chain Explorer synthetic receipts (2026-11-14 ~01:21 EST)

  • Gap: a chain demo needs more than one receipt; only one real v1.0 receipt exists on disk (pipeline run rcpt-20261114-0001).
  • Decision: receipts 2 and 3 are synthetic follow-ons, labeled SYNTHETIC on the page, with hashes computed for real with Node crypto (not fake values).
  • Rationale: the chain mechanics must be demonstrable end to end; labeling keeps synthetic data from ever being mistaken for a real receipt.
  • What would change it: real receipts from a production run would replace the synthetics.

D-003, Organism State Dashboard Supabase row (2026-11-14 ~01:21 EST)

  • Gap: production Supabase status cannot be probed from here (no saved login, no direct access).
  • Decision: mark DOWN on dated record only (unreachable since ~Oct 16, lead pull failed 29 nights), and state on the row what would verify it.
  • Rationale: an honest DOWN-with-evidence beats an UNKNOWN that hides a known outage, and beats a fake live probe.
  • What would change it: a successful direct probe or a Mac-side check.

D-004, Vault Concept Explorer has no tier filter (2026-11-14 ~01:41 EST, builder finding, recorded by coordinator)

  • Gap: the explorer brief asked for a tier filter (A/B/C/GATE), but no tier field exists anywhere in the census data (Master-Data-List.json).
  • Decision: no tier filter offered, no tier assigned to any row. The page and hub card state plainly that tiers are not in the census data.
  • Rationale: assigning tiers would be inventing data. A tier scheme must be defined and assigned by a human or a court pass first.
  • What would change it: a court pass or Jeramie assigning tiers to the 246 concepts, after which the explorer can add the filter.

D-005, Unified chain worked-example byte values (2026-11-14 ~06:24 EST, builder decision)

  • Gap: the N-Cell paper defines the 8-byte header layout only; it gives the recorded stamped hex for claim OPP-2026-RE-0042 but not the per-byte input values that produce it.
  • Decision: route 0x1f, organ 0x07, lifecycle 0x01, authority 0x07, memory 0x0f, confidence 165, risk 45, output 0x01, chosen so the stamper reproduces the recorded hex 1f0701070fa52d01.
  • Rationale: the worked example must be reproducible by the tool, not just displayed; the byte values are the builder's reconstruction, not a paper claim.
  • What would change it: paper-defined byte values for the example, or a different recorded example.

D-006, Unified chain promotion rule differs from governance-loop demo (2026-11-14 ~06:24 EST, builder decision)

  • Gap: no paper defines the full promotion rule across intersection, CRUCIBLE, and write-gate together.
  • Decision: promote when intersection is PROCEED, CRUCIBLE is not KILL, and write-gate is WRITE or QUARANTINE with explicit override noted. An ITERATE crucible can therefore promote here. The governance-loop demo additionally requires SHIP-CANDIDATE plus external signal; the two demos now differ, and both pages state their rule.
  • Rationale: the task brief defined this rule for the flagship; keeping the older demo's stricter rule would have silently contradicted the brief.
  • What would change it: a canonical promotion rule from Jeramie or a court pass, applied to both demos.

D-007, Unified chain blockedPolicy vs blockedInfra split (2026-11-14 ~06:24 EST, builder decision)

  • Gap: the paper defines the intersection formula but does not split blocked edges into kinds.
  • Decision: blockedPolicy means not allowed; blockedInfra means allowed but not available. Both lists shown with counts.
  • Rationale: the distinction is what a user needs to act on (policy change vs provisioning), and the split is visible in the verdict instead of hidden.
  • What would change it: a paper-defined taxonomy of blocked reasons.

D-008, Unified chain QUARANTINE override (2026-11-14 ~06:24 EST, builder decision)

  • Gap: no paper defines how a quarantined memory write may proceed.
  • Decision: a checkbox override, off by default, recorded in the receipt payload as overrideUsed.
  • Rationale: quarantine must be escapable by an explicit human act, and that act must leave a receipt trail; a silent bypass would defeat the gate.
  • What would change it: a governance rule forbidding override, or a founder-defined override authority.
