  1. So what happens when we “scrape”?

There are really four separate operations.

Operation 1: Source discovery

We identify a useful authoritative data source.

Example:

text Berrien County Treasurer ↓ Tax delinquency dataset

or:

text Register of Deeds ↓ Recorded deed / ownership data

or:

text GIS / assessor ↓ Parcel + property characteristics

Operation 2: Acquire it

This is LandOS Ingest / Source Factory.

Depending on the source, acquisition could be:

text API call CSV download PDF download HTML retrieval public portal query bulk county file manual import scheduled fetch partner feed

But we do not want:

text scrape → throw data into database

We want:

text SOURCE ↓ RAW ARTIFACT ↓ TIMESTAMP ↓ HASH ↓ SOURCE METADATA ↓ MANIFEST ↓ CUSTODY

So later we can say:

This fact did not magically materialize in our database. Here is where it came from, when we retrieved it, what version we received and which raw evidence supports it.

The current architecture specifically assigns raw acquisition, source, time and ingestion custody to LandOS Ingest. DeedSonar_Production_Brief_2026…

  1. Then LandOS normalizes it

Raw county data is ugly.

One system might say:

text 120 N MAIN STREET

Another:

text 120 N MAIN ST

Another:

text Parcel 11-02-1234-0001-00-0

Another has:

text HICKS JERAMIE S

Another:

text Jeramie S. Hicks

So LandOS Engine attempts to resolve:

text SOURCE RECORD A ─┐ SOURCE RECORD B ─┼──> CANONICAL PROPERTY SOURCE RECORD C ─┤ SOURCE RECORD D ─┘

and:

text OWNER RECORD A ─┐ OWNER RECORD B ─┼──> CANONICAL OWNER / ENTITY OWNER RECORD C ─┘

Then it creates normalized facts and signals.

Example:

text FACT tax_balance = $18,421

FACT owner_mailing_state = FL

FACT last_transfer_year = 1991

SIGNAL absentee_owner = true

SIGNAL long_term_ownership = true

SIGNAL tax_distress = true

Critically, unknown information stays unknown rather than silently becoming 0 or false. That same doctrine is already demonstrated downstream in DeedSonar; unknown economics remained NULL, not fake $0. DeedSonar_Production_Brief_2026…

So we are effectively encoding how an expert thinks about a particular acquisition thesis.

That is a lot more powerful than “scrape Zillow.”

  1. The one distinction you absolutely need to preserve RUN RECIPE ≠ SCRAPE / REFRESH SOURCE

This is the part I would make explicit in the UI.

Today:

text RUN RECIPE ↓ evaluate what we already possess ↓ seconds ↓ results

Future/source-refresh mode:

text REFRESH SOURCES ↓ connect to county/API/files/etc. ↓ retrieve source ↓ custody + hash + manifest ↓ normalize ↓ reconcile property identities ↓ update estate ↓ run recipe

A source refresh could take considerably longer, involve rate limits, file retrieval, manual acquisition or systems outside our control.

The architecture intentionally treats those as different operations. DeedSonar_Production_Brief_2026…
