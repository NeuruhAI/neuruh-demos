7Design decisions (mine, labeled)

Nothing in this section is a paper claim. Each decision below was made by this build because the sources do not define it.

  • Swap rules. (1) Every occurrence of the exact token string is replaced with the replacement verbatim. (2) No partial matches: [SCENE] never matches [SCENE_DESCRIPTION]. (3) Locked text is never a slot and is verified unchanged by the drift check. (4) One token per run. (5) The replacement is inserted verbatim, no escaping, no case changes; if it contains brackets the bracket-balance check fails, which is the correct behavior. (6) An empty replacement is allowed to run and fails the non-empty check, so the check is demonstrable.
  • Token forms. The source uses both [LOCKED: ...] and <ANGLE_TOKEN>. The simulator accepts square-bracket and angle-bracket tokens. T1 keeps the source's angle-bracket form verbatim.
  • Drift criteria and thresholds. Six checks, all computed for real: bracket balance; swapped token gone; locked block intact (N/A when a template has no locked block); replacement non-empty; length ratio within 50% to 200% (my threshold); word-count delta within 30 words (my threshold). Word count is whitespace-split. No semantic check exists and none is claimed.
  • Template assembly. T2, T3, and T4 assemble stated fields into template form; the assembly is mine and each card says so. T5 assembles the stated IPP code-generation sentence into template form. T1 is verbatim from the source. T6 pairs the stated X format rule with verbatim bank facts.
  • Default values. T2 and T3 defaults come from the stated /image style direction (dark UI, tactical/command-center, emerald and slate). T4 defaults are the four stated values from the session log. T5 defaults are my choices. T6 defaults are bank item 10 and the stated cal.com/neuruh link.
  • Receipt ids. tok-20261114-0001 and up, per session run. This demo's chain is separate from the pipeline first-run receipt rcpt-20261114-0001 in the receipt-chain-explorer.
  • SHA-256. A synchronous pure-JS implementation, so the same code path runs in the browser and in the Node test. Verified against Node crypto on vectors including the empty string, "abc", a 56-character RFC vector, a 1,000-character input, a unicode input, and real canonical receipt JSON (see build report).
  • FACT picker. When the T6 FACT token is selected, a dropdown offers all 30 bank items verbatim with their proof shown. Choosing one fills the replacement value.

8Gaps (honest)

  • No standalone Token-Swap Prompting dossier exists in the vault. The framework is known only through mentions in the HQ-Hub L1 knowledge base, the IPP methodology, the Command Codex /image command, the registry label index, and the session log.
  • No source states swap rules, drift criteria, thresholds, or a banned-word list. All of those on this page are this build's design.
  • No source states a repo, an owner, a runtime, a tier, or dependencies for Token-Swap Prompting. All are UNKNOWN or NO REPO on the status board.
  • Token-Swap P5 canonical name is still undecided (Sunset Silhouette vs Workshop Focus), per vault CRE-006. That open item belongs to the separate Token-Swap Image Protocol concept and is not resolved here.
  • The Quantum Prompt Lattice note says Token-Swap is its language lineage ("Token-Swap to QPL") with a Constraint Domination Protocol collapse engine, but no source defines how the two connect mechanically. Not modeled here.
  • Bank item facts in the T6 picker are reproduced verbatim, including their stated list prices and the camper listing figures. Those are source facts, not valuations of Token-Swap Prompting. No valuation of the framework is made anywhere on this page.
  • Layout was not eyeballed in a live browser by this build; behavior, swap logic, drift checks, and hashes were tested in Node (see the build report).
