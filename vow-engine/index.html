04Spec reference

The storage layer and pipeline this demo mirrors, from the source spec.

SQLite schema (spec):
vows(id PK, timestamp ISO8601, raw_text, embedding BLOB)
meta(key PK, val)

Pipeline (run_vow_engine.sh):
1. src/analysis/evolution.py  - growth vs drift
2. src/export/top_beliefs.py  - CSV + Markdown export

Weekly cron (spec):
0 7 * * MON  cd ~/Projects/vow_engine \
  && ./run_vow_engine.sh >> cron.log 2>&1

Maintenance (spec):
- Quarterly: sqlite3 db/vows.db 'VACUUM;'
- Model update: re-embed all rows
- Drift review: every drift row, by hand

Source: "FOUNDER'S CODEX VOW ENGINE - COMPLETE BUILD SPEC" (Google Doc, 2025-07-13), built as item s06-founder-s-codex-vow-engine-complete-build-spec in the Drive build-out. Honest state: this page is a browser simulation of the spec's logic. The real spec stores embeddings from OpenAI text-embedding-3-small in SQLite and needs an API key; this page computes a deterministic local pseudo-embedding instead: each word is hashed into a 64-dimension vector, so identical and near-identical sentences score close together and unrelated sentences score far apart, which is enough to demonstrate the growth/drift detector but is not a semantic embedding. Vows are kept in this browser's local storage only; Clear all vows wipes them. The spec's integration targets (investor decks, LinkedIn bio, Mirror-Agent GPT, Notion OS) are listed in the spec, not wired here. Threshold 0.15 and top_n 12 are the spec's defaults, not tuned values.
