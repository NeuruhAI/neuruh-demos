3. The Learning Loop and Learning Log

What it is. The Learning Loop is the segment program's record-and-improve mechanism. After each execution, one entry is written the same day, before the next execution starts. The Learning Log is the record itself. The loop does not make founder decisions, does not send messages, make calls, or post content, and does not invent numbers.

What it teaches or records. Each entry records what was attempted, what happened with evidence, whether the customer got value first (full, partial, or no), what was learned, what changes next time, what stays blocked and who owns the unblock, and a status of open, closed, or blocked. A loop closes only when the recorded change is applied in a later execution and the result is recorded. A weekly rollup runs every Monday and names loops closed, loops still open, blocked items and owners, and the single biggest change for the next week. The first rollup is due Monday 2026-11-23.

Where it lives. Local files ~/workspace/segments/learning-loop.md (70 lines) and ~/workspace/segments/learning-log.md (176 lines). No live URL exists for either file as of 2026-11-18. This master document is their first live, public-facing home.

State. IMPLEMENTED. The loop definition and the log are written and in use, with 6 entries and 16 blocked items recorded. It is not LIVE as a published page, not TESTED through a full weekly rollup cycle (first rollup due 2026-11-23), and not PROVEN, because no loop has yet closed through a second execution.

The test every entry is judged against. Did the customer get value first? A phase that only produced documents for Jeramie scores partial at best. A phase that put something useful in a customer's hands scores full.

6. Prompt Builders and Examples Library

What it is. Prompt Builders is a browser app of 26 builders that turn canon source material into fill-in-the-fields prompt templates. Each builder carries fields, a verbatim template where one exists, a source document and section, and seeded worked examples. The Examples Library is the worked-examples layer added 2026-11-18: every builder has an Examples Library panel with seeded examples from the canon, plus any examples Jeramie adds in the browser. Nothing in the library changes a builder's fields, template, state, or notes.

What it teaches. Each builder teaches one repeatable production pattern from the canon: estate and house image generation, token-bank systems, technical direction anchors, negatives and conditional tokens, compositing protocols, resale listing generation, AaaS packaging, discipline prompts, and builder frameworks. The examples teach by showing full prompt text and finished outputs, hash-verified from the canons, with nothing invented.
