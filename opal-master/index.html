2. What Opal is, on this evidence

On the evidence in front of this document, Google Opal is the Google service at opal.google where Jeramie built apps that Drive stores as Breadboard graph JSON files. That is the full verifiable definition available here. It rests on two facts: every Opal app in the inventory carries the MIME type application/vnd.breadboard.graph+json, and every one opens at an opal.google/open/<id> link. No product documentation, pricing, account state, or run history for Opal was read as part of this audit, and none is claimed.

What an Opal app file is, in practical terms: a saved graph, not a deployed service. The graph JSON describes nodes and connections. Whether the graph is complete, whether it calls any live model or API, whether it was ever run end to end, and whether anyone can use it today are all UNKNOWN for all six apps, because no graph JSON was downloaded, parsed, or executed on this VM, and no live browser session was available to open opal.google.

The state ladder used in this document

CONCEPT, DESIGNED, IMPLEMENTED, TESTED, DEPLOYED, LIVE, PROVEN, COMMERCIAL, BLOCKED. DESIGNED is not DEPLOYED is not LIVE is not PROVEN. A stored file is IMPLEMENTED as a stored file only. Nothing in the Opal record reaches TESTED, DEPLOYED, LIVE, PROVEN, or COMMERCIAL on the evidence here, because no app was run, no deployment was found, and no revenue or usage exists on record. MRR is $0.

Content verifiedYes, from the local uploaded copy of the same text (216,377 bytes, 9 pages, read in full via pdftotext) and the Token-Swap Canon v1.1, which absorbs it as source 1
StateImplemented, method documented; canon Live

What it is. The original worked example of the token-swap image method: one master template for a 200-acre luxury estate, with a locked foundation and swappable tokens. The foundation is the visual DNA that never changes: technical specs, core subject, environment, and style directives. The tokens are the variables, marked with tags such as <ANGLE_TOKEN>, <SEASON_TOKEN>, and <MOOD_TOKEN>.

What is verifiable about it. The full template was read in this audit. Subject: 200-acre luxury estate, fusion of modern smart-home tech, Southern plantation grandeur, and Lake Tahoe mountain lodge. Camera block (TECH): f/8 hybrid cinelens (24 mm plus 50 mm blend), ISO 100, 1/320 s, 12-bit RAW color depth in this source. Negative block: cartoonish, over-saturated HDR, tilt-shift gimmicks, fisheye, blown highlights, muddy shadows, AI glitches, warped geometry, watermark, text artifacts. Angle tokens P1 to P7: P1 Aerial Overview, P2 Front Elevation, P3 Pool-Deck, P4 Interior-Exterior, P5 Workshop Focus in the full list, P6 Equestrian Angle, P7 Water Feature Drama. Season tokens: Spring, Summer, Autumn, Winter. Mood tokens: Serene luxury, Dynamic drama, Warm welcome.

Open conflict, carried forward. The source lists P5 two different ways: the early example list says P5 Sunset Silhouette, the full P1-P7 list says P5 Workshop Focus. The Token-Swap Canon v1.1 flags this in place and no canonical P5 has been chosen. This document repeats the flag and does not resolve it.

Byte note. The Drive file is listed at 135,701 bytes. The local uploaded copy read here is 216,377 bytes. Byte identity between the Drive file and the local copy is NOT verified, so the content claim rests on the local copy and the canon, not on a byte match to the Drive file. The text read matches the canon’s source 1.

Verdict: IMPLEMENTED as a documented method. The method lives on in the Token-Swap Canon v1.1 (LIVE) and the Token-Swap Lab and Token-Swap Studio builds (Section 8). The PDF itself was not re-read from Drive in this audit.
