Agent-First Source Control: Behavioral Traits and Topology

Date: 2026-11-16 Phase: 2, after the phase 1 demo of 2026-11-16 Phase 1 demo: https://neuruhai.github.io/neuruh-demos/agent-first-source-control/ Resolution doc: ~/workspace/segments/agent-first-source-control-resolution.md Data file: ~/workspace/agent-first-topology/topology-data.json Status: DRAFT. The demo is a browser-local simulation, not a real transport.

Plain statement, carried over from phase 1: GitHub is still the transport and the demo host. The estate has NOT replaced GitHub. What exists is the governance and review layer GitHub lacks, mostly as browser simulations or specs. This document says what agents are like as the primary players in source control, and what system that behavior forces. The Anthropic internal source-control claim stays UNVERIFIED. It is the poster claim only. No evidence for it is in the estate.

Pattern: modeled on the Neuruh Topology demo (44 nodes, 35 edges, 12 mission-loop stages, 12 blocked seams, ~/workspace/neuruh-topology/index.html, 2026-11-15) and the Retardio System map (9 components, 12 blocked seams, ~/workspace/retardio-system/index.html, 2026-11-15).

State ladder: CONCEPT, DESIGNED, SCAFFOLDED, IMPLEMENTED, TESTED, INTEGRATED, DEPLOYED, LIVE, OBSERVED, PROVEN, COMMERCIAL. Implemented is not deployed is not live is not proven.

Counts: 9 traits, 22 nodes, 35 edges, 11 mission-loop stages, 10 blocked seams.

1. Behavioral traits

Nine traits. No trait was merged or split. The starting set held against the evidence as read. Each trait carries its state and the scope of that state, because a trait proven in one run is not proven everywhere.

T1. Volume and parallelism

What it means: agents generate far more change volume than humans, in parallel, around the clock. A review system sized for human pull request rates will drown.

Estate evidence:

  • ~/workspace/research-drift-2026-11-14/overnight-run-log.md, 2026-11-14: Wave 1 audit checked 143 hub cards in about 5 minutes using 4 parallel audit agents (00:56 to about 01:01 EST).
  • Same file, 2026-11-14: waves ran 4 to 5 agents in parallel through the night (00:56 to about 05:55 EST). Wave 2 fixed 17 items in about 15 minutes. Meme batches rendered 48, 22, 20, 20 and 20 images in single batches.
  • ~/IDENTITY.md, 2026-09-16: LANDOS hunt job 6071b7ad scored 153 leads and synchronized 153 leads to CRM in one run.

What it forces: review must be per change packet, not per comment thread, and must run without a human in the per-packet path. Volume is absorbed by parallel isolated reviewers and a deterministic gate, not by adding human reviewers.

State: PROVEN. Scope: proven for agent build volume in the overnight run and for lead scoring volume in the 2026-09-16 hunt job. Not yet proven against real pull request volume through a review queue. That part is DESIGNED.

T2. No persistent memory across sessions

What it means: agents forget between sessions. The system must remember for them. The receipt chain is the memory.

Estate evidence:

  • ~/IDENTITY.md, section 19: context loss is the estate central problem, listing stale documentation, duplicated work, forgotten receipts, unclear canonical sources and repeated archaeology.
  • ~/workspace/research-drift-2026-11-15/daybreak-solution-adaptation-map.md, 2026-11-15: Memory Gate decay rule recorded as F(t)=2^(-t/h). Patches that worked become memory, patches that failed become negative lessons, with decay and quarantine.
  • ~/workspace/retardio-system/index.html, 2026-11-15: Done/Open Ledger holds 118 items (Done 43, Open 65, Unknown 7, In flight 3) with 118 v1.1 receipts chained from GENESIS, chain head 76675cc07b629bbea8b76717e282fdb89d05d519953562e22aa75a134666dcad, CHAIN VALID in Python and JS.
  • ~/workspace/research-drift-2026-11-14/overnight-decisions.md, 2026-11-14: decisions D-005 to D-008 were recorded in writing by the overnight coordinator because they would otherwise be lost. The log states they are builder decisions, not Jeramie orders.

What it forces: every consequential action writes a hash-chained receipt before it counts. Nothing is trusted to an agent session memory. The chain, not the agent, carries state forward.

State: PROVEN. Scope: proven that the estate loses context without written receipts, and that chained receipts survive as memory. The receipt chain as the sole memory for source-control review is IMPLEMENTED in the demo, not yet proven on real reviews.

T3. Need machine-readable verdicts, not prose

What it means: agents cannot read threads. A verdict must be a value a machine can act on, with the exact failing claims named.

Estate evidence:

  • ~/workspace/agent-first-source-control/index.html, 2026-11-16: CRUCIBLE eta verdict, eta = (I_q I_r I_v) / (1 + E_wasted + C_violations), clamped 0-100, threshold 70. PASS needs eta at or above 70 AND uncited count zero.
  • ~/workspace/research-drift-2026-11-15/daybreak-solution-adaptation-map.md, 2026-11-15: CRUCIBLE returns uncited claims by exact text. PASS publishes, FLAG returns the claims to fix.
  • Same file, 2026-11-15: N-Cell/64 header is 8 bytes (routeMask, organMask, lifecycleMask, authorityMask, memoryMask, confidence, risk, outputMask).
  • ~/workspace/segments/agent-first-source-control-resolution.md, 2026-11-16: complaint table. Threads become overwhelming and unreadable quickly. The estate answer is seven-agent isolated review, one verdict per agent, one adjudicated outcome.

What it forces: review output is a verdict enum plus a list of exact failing claims, never a comment thread. The change packet carries the diff, the N-Cell/64 authority header, the claim set and the evidence in one machine-readable unit.

State: IMPLEMENTED. Scope: implemented as a browser simulation in the phase 1 demo. No real pull request has been reviewed by this verdict format, so it is not PROVEN.

T4. Correlated errors and phantom consensus

What it means: agents converge on each other errors. Agreement after interaction is not independent confirmation. Isolated parallel review exists to stop that.

Estate evidence:

  • ~/workspace/research-drift-2026-11-15/daybreak-solution-adaptation-map.md, 2026-11-15: Grok consensus advice pasted 2026-11-15. Failure modes named are correlated errors, phantom consensus and uncalibrated aggregation. New specifics: composed probability by scaled log-odds or dependence-aware pooling, phantom-consensus measurement as the gap between private findings and post-interaction findings, structured abstain, per-plugin reliability, debate limit, public eval set.
  • Same file, 2026-11-15: Sentinel Court attack surface. Swarms: 20 identical workers are not 20 independent confirmations.
  • Same file, 2026-11-15: Organization Compiler. Swarm diversity enforced, 20 identical agents are not 20 independent opinions. Bayesian reliability per worker per task family.
  • ~/workspace/agent-first-source-control/index.html, 2026-11-16: each review agent reads only the packet, in isolation. No agent reads another agent output. Confidence is seeded by a deterministic hash of the packet text plus the lens name.

What it forces: review runs in isolation first, then deliberation, then a Chair. Private verdicts are logged before any interaction so the private vs post-interaction gap can be measured. Agreement is composed by dependence-aware pooling weighted by per-agent Brier scores, never by majority vote.

State: DESIGNED. Scope: the isolation mechanism is implemented as a simulation. The phantom-consensus measurement itself is unproven in the estate. Zero resolved forecasts exist to score against, so no private vs post-interaction gap has ever been measured. See blocked seam S10.

T5. Need explicit authority

What it means: AI generates, founder authorizes, system executes (G-1). Agents do not self-authorize. Every proposed action carries who authorized it, the scope, the expiry and a single-use token.

Estate evidence:

  • ~/workspace/research-drift-2026-11-15/six-layer-upgrade-spec.md, 2026-11-15, Layer 3: every proposed action must carry an authority header stating who or what authorized it, the scope, the expiry and the single-use token or equivalent. The policy gate can DENY or ESCALATE independently of the model. Human approval remains mandatory for any action that leaves the system or affects external state.
  • ~/workspace/convergence-100/TEST-REPORT.md, 2026-11-15: run_tests.py 91/91. Authority and gate section 29/29. Export without header DENIED, expired header DENIED, revoked token DENIED, token reuse DENIED, export without human approval DENIED, approved_by=system DENIED, model approval cannot override DENY.
  • Same file, 2026-11-15: Layer 3 authority is authorizer, scope, expiry, 256-bit single-use token, deterministic DENY/ESCALATE gate, revocation list, gate receipt chain verifies (17 receipts).

What it forces: no packet reaches review without a valid authority header. The gate is deterministic and independent of the scoring function. A merge is an external action, so it always needs founder approval. The system prepares the packet, it cannot send it.

State: PROVEN. Scope: proven in real test code (91/91, including 29/29 authority and gate checks). Live enforcement against a real repo host is not built. Credential provisioning is BLOCKED (seam S1).

T6. Produce unverified claims unless gated

What it means: agents state claims as fact. Nothing promotes on a claim alone. Promotion needs a passing gate plus a real external signal, and provisional machine decisions stay provisional.

Estate evidence:

  • ~/workspace/retardio-loop/BUILD-NOTE.md, 2026-11-15: proof run 3. Baseline_v2 proposed through the gate and REJECTED (resolved 0 below the 200 threshold, Brier NOT YET COMPUTABLE). Rejection receipted, rule stays baseline_v1.
  • ~/workspace/research-drift-2026-11-15/daybreak-solution-adaptation-map.md, 2026-11-15: Governance Loop. Only a claim that passes all three gates AND carries a real external signal promotes. P0 Seam: KILL below 20 or 3 strikes, ITERATE 20-49, SHIP-CANDIDATE at or above 50 only with a real external signal.
  • ~/workspace/research-drift-2026-11-14/overnight-decisions.md, 2026-11-14: D-005 to D-008 are provisional machine decisions, recorded as builder decisions, not canon, until Jeramie adopts them. D-006 records that the unified chain promotion rule differs from the governance-loop demo rule.
  • ~/workspace/research-drift-2026-11-14/overnight-run-log.md, 2026-11-14: Wave 1 audit found 12 unproven-claim cards and 12 stale cards across 143 checked. The fix wave relabeled LIVE tags on 11 simulation cards to SIMULATION or DEMO.

What it forces: the eta gate, the CRUCIBLE verdict and the promotion gate sit in the promotion path, not beside it. A failed gate blocks promotion by default. Every gate decision is receipted, including rejections.

State: PROVEN. Scope: proven that the gate rejects in a real run (retardio run 3) and that ungated claims were found and corrected in the overnight audit. The canonical promotion rule is not settled. D-006 records two demos with different rules, so the rule itself is a blocked seam (S9).

T7. Need dedup

What it means: recursion without dedup re-issues the same work. A loop that cannot tell new from seen will flood the review queue with repeats.

Estate evidence:

  • ~/workspace/retardio-loop/BUILD-NOTE.md, 2026-11-15: proof run 2 fetched 25 observations (0 new) and issued 0 new forecasts. Proves recursion plus dedup. Run 2 read run 1 state and continued from it.
  • ~/workspace/retardio-loop/run-log.txt, 2026-11-16: run 6 (2026-11-16T12:23:16Z) fetched 25, 0 new, 0 new forecasts, status OK. Six runs total, 20 forecasts, zero duplicate forecasts for any observation_id.
  • ~/workspace/segments/agent-first-source-control-resolution.md, 2026-11-16: PR volume strain answer cites the Retardio loop dedup proof, and states plainly that dedup is proven only in the Retardio loop, not in a review queue.

What it forces: every packet and every observation is deduped by content hash (observation_id is SHA-256 of canonical payload) against persistent state before review starts. A repeat packet is a no-op with a receipt, not a second review.

State: PROVEN. Scope: proven in the real Retardio loop across 6 runs. Not yet proven in a review queue. No real pull request volume has run through this dedup.

Estate evidence:

T9. Human traits in the loop

What it means: the founder is the source of intent and consequential authority. The human is the authorizer and exception handler, not the typist.

Estate evidence:

  • ~/workspace/research-drift-2026-11-15/six-layer-upgrade-spec.md, 2026-11-15, Layer 3: human approval remains mandatory for any action that leaves the system or affects external state. The system can prepare the packet, it cannot send it.
  • ~/workspace/convergence-100/TEST-REPORT.md, 2026-11-15: gate test 53i, export without human approval DENIED. Gate test 53j, approved_by=system DENIED. Gate test 54, probability at or above 0.80 escalates, escalation queued with receipt attached, human holds escalation.
  • ~/IDENTITY.md, section 19: the estate is larger than one human continuously maintained mental model, which is why the human cannot be the typist for every change and must instead be the authorizer.
  • ~/workspace/research-drift-2026-11-15/daybreak-solution-adaptation-map.md, 2026-11-15: Cockpit. The human-accountable surface for declaring intent, inspecting evidence, assigning resources, approving consequential action, monitoring execution, reviewing outcomes.

What it forces: the human appears at exactly three points. Intent (the mission), authorization (the gate), and exception (escalation, quarantine override, rollback decision). Everything between those points is machine work with receipts.

State: PROVEN. Scope: proven that the gate enforces human approval in real test code (91/91). The production exception-handler workflow for source control is DESIGNED, not yet run, because no live promotion service exists (seam S6).

5. Blocked seams

10 seams. The six gaps from phase 1 (resolution doc section 5, 2026-11-16) are S1 to S6, in resolution order. S7 to S10 are the additional blocks that touch this system. DeedSonar 503 and Supabase unreachable are left out. They do not touch this system.

S1. Identity

What is blocked: no live identity provider. Who the agent is, who authorizes, what scope, what expiry. Provisioning, key management and revocation that works when a key leaks are not built.

What unblocks it: a real identity provider wired to the N-Cell header and gate, with provisioning, rotation and a working revocation list.

Whose decision: Jeramie. Pick the identity approach and fund the build. Order of work in the resolution doc puts identity first, before diff engine, CI, transport, hosting and the live promotion service.

S2. Diff engine

What is blocked: no real diff engine. The demo reviews pasted packets, not real diffs from a real repo. Hunks are not mapped to files, functions or blast radius.

What unblocks it: a parser plus a language-aware layer that maps real diffs to files, functions and blast radius and feeds the review swarm.

Whose decision: Jeramie. Product direction call on whether this graduates from simulation toward a real transport (resolution doc section 7, item 3).

S3. CI runner

What is blocked: no real CI. Tests, lint, type checks and security scans do not run against the change in an isolated runner. The eta formula exists. The signals that feed it do not, except by hand.

What unblocks it: runner infrastructure plus result ingestion into the CRUCIBLE eta verdict.

Whose decision: Jeramie. Same graduation call as S2.

S4. Git transport

What is blocked: no real git transport. No clone, fetch, push, refs or packfiles. Without this there is no source control product, only a review page.

What unblocks it: either implement git hosting or wrap an existing git server and accept its limits. Largest single build of the six gaps.

Whose decision: Jeramie. Same graduation call as S2.

S5. Repo hosting

What is blocked: no repo hosting. Storage, access control, webhooks and uptime for real repos are not built. GitHub Pages hosts demos free. Hosting real repos is a different commitment.

What unblocks it: hosting infrastructure and operations, or an accepted dependency on an existing host with its limits stated.

Whose decision: Jeramie. Same graduation call as S2.

S6. Live promotion service

What is blocked: no live promotion service. The promotion gate exists only as a demo control and as gate code in convergence-100. The unified-chain demo is not a service with a database, a queue and an operator.

What unblocks it: turn the unified-chain demo into a service (database, queue, operator, automatic rollback, Sentinel Court as independent verifier). The Retardio loop is the only live proof this pattern runs unattended, once a day on public data.

Whose decision: Jeramie. Same graduation call as S2.

S7. On-chain anchor write

What is blocked: Anchor v2 criterion 2, actual chain write, is BLOCKED. The execution path is built (ots_anchor.sh, Solana memo template, Base/Polygon calldata templates, human approval gate). No chain write, no wallet, no spending.

What unblocks it: Jeramie picks a chain and a wallet. Until then every receipt carries anchor_root null.

S8. Outcome resolution

What is blocked: learning cannot score anything until outcomes resolve. The Retardio loop has 20 forecasts, 0 resolved, Brier NOT YET COMPUTABLE. The assessor source carries only the latest sale per parcel, no grantor, no deed history, no formation dates.

What unblocks it: recorder bulk data or per-parcel record cards for deed history, plus Secretary of State formation dates. For source control, the equivalent is real merge outcomes recorded in the Outcome Ledger over time.

Whose decision: Jeramie. Data source call for the measurement side. The source-control side resolves itself once real merges run through the loop.

Source: ~/workspace/retardio-loop/BUILD-NOTE.md, 2026-11-15, blocked section.

S9. Canonical promotion rule conflict

What is blocked: two demos promote on different rules. The unified chain promotes when intersection is PROCEED, CRUCIBLE is not KILL, and write-gate is WRITE or QUARANTINE with explicit override. The governance-loop demo additionally requires SHIP-CANDIDATE plus a real external signal. An ITERATE crucible can promote in one and not the other.

What unblocks it: a canonical promotion rule from Jeramie or a court pass, applied to both demos.

Whose decision: Jeramie. Define the canonical rule. Recorded in overnight decision D-006, 2026-11-14.

Source: ~/workspace/research-drift-2026-11-14/overnight-decisions.md, 2026-11-14, D-006.

S10. Phantom-consensus measurement unproven

What is blocked: no private vs post-interaction gap has ever been measured. The measurement needs resolved outcomes to score private verdicts against, and there are 0 resolved forecasts. Per-plugin reliability and per-agent Brier weights cannot be computed without a held-out eval set.

What unblocks it: resolved outcomes (S8) plus private verdict logging in a real run, plus a public eval set of known-vulnerable and known-benign cases per the Grok advice.

Whose decision: Jeramie. Eval set call and the S8 data call. No founder decision can substitute for resolved outcomes.
