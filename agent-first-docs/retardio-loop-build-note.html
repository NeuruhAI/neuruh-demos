The loop, per run

  • Kill-switch check first: if KILL exists, halt before fetching, append a halt receipt, log, exit 0.
  • Fetch the ArcGIS query (WHERE NAME_1 LIKE '%LLC%' AND SALESPRICE IS NOT NULL AND SALESDATE IS NOT NULL, 25 rows, SALESDATE DESC), record response SHA-256. Best-effort count query on the same endpoint keeps the sample frame current. Fetch failure → error observation receipted, exit 1, nothing fabricated.
  • Build + validate observations; dedup against state.json (recursion: run N continues from run N-1).
  • Issue rapid_flip forecasts under baseline_v1 (prior 0.04, +0.03 if consideration < $100,000, +0.02 if acreage < 0.5, clamp [0.01, 0.50]) for new deed observations only; dedup by observation_id.
  • Resolution check: 0 codable, the assessor carries only the latest sale per parcel, no grantor, no deed history, no formation dates. Recorded honestly.
  • Brier only when resolved > 0; otherwise Brier NOT YET COMPUTABLE, 0 resolved.
  • Promotion gate: a rule change is proposed only via explicit --propose-rule; accepted ONLY if Brier improves on held-out data AND resolved >= 200. Otherwise REJECTED with accepted: false.
  • Append run receipt, update state.json, append one run-log line.

Governance: the loop never sends, posts, emails, messages, spends, or acts outside the system. It reads one public endpoint and writes local files only. No private-individual scoring. No Brier, resolution, or promotion fabricated.

Exact command to run the loop

python3 ~/workspace/retardio-loop/loop.py

Propose a rule change through the gate (explicit only; the loop never self-proposes):

python3 ~/workspace/retardio-loop/loop.py --propose-rule baseline_v2

Verify the chain offline:

python3 ~/workspace/retardio-loop/verifier.py
