1. Read this first: DESIGNED vs VERIFIED

What is designed here

The scorer formula in section 3 is my design decision, written for this demo on 2026-11-14. It is not a paper formula, not a LANDOS formula, and not a codex formula. No source states how territories should be weighted against each other, so this demo invents the weighting openly, labels it, and shows every step. Change the weights and the ranking changes; that is the point of the calculator.

What is verified

Only three things on this page were verified live by a run this week: the St. Joseph County ArcGIS endpoint and its counts (pipeline first run, 2026-11-14, 5 signals pulled, 3 verified against county record cards), the NeuruhAI/territory-engine repo contents (checked 2026-11-14), and the live Ecosystem Codex page (fetched 2026-11-14). Everything else is a dated snapshot from a named dossier, labeled HISTORICAL with its date.

Tier definitions (Ecosystem Codex, live page)

This demo is a Tier B artifact about it: built and inspectable, not proof the engine runs.

4. Territory scorer (interactive calculator)

Design decision, labeled as mine. No source states how to weight territories against each other, so this demo defines its own formula. It is a demonstration of scoring mechanics, not a LANDOS formula and not a paper formula. Every input below is a stated fact from Table 1 or UNKNOWN. A missing input contributes 0 to its term and is flagged, never silently filled.

score = Ws x (rows / 27,343) + Wc x (scored / rows) + Wr x (recipes / 4) + Wv x verifyFactor Defaults: Ws 40, Wc 25, Wr 20, Wv 15 (sum 100). Weights are normalized to sum 100 if you move the sliders. rows = owner-lead rows, Sep 22, 2026 snapshot. Denominator 27,343 is the largest stated count (Davidson). scored/rows = scored share where both numbers are stated; UNKNOWN where either is missing (term 0, flagged). recipes / 4 = hunt recipes with STATED coverage of the territory, out of the 4 active recipes. verifyFactor = 1.0 St. Joseph (live endpoint plus 3 of 5 signals verified 2026-11-14) 0.5 Berrien (6 of 40 signals verified live at a county point in the source session) 0.0 everywhere else (nothing stated; LaPorte endpoint not located)

7. The 49-signal model behind the scorer (reused, not re-derived)

From the live recipe-ingredient-registry demo and the LandOS codex dossier, reused verbatim in summary:

  • LandOS scoring model: 49 signals (Ecosystem Codex, Tier A as a model), split 15 structure / 14 land / 14 owner-event / 6 market, family weights sum to 1.0.
  • 40 named, 9 unknown. The 9 unnamed signals (1 structure, 2 land, 6 market by arithmetic) are a gap, not rows. The 49 vs 50 count dispute is unresolved across batches 003, 004, 007, 008, 009, 013.
  • 6 of 40 computed real values against a Berrien County point in the source session: flood zone, slope, water adjacency, road access, tree canopy, vegetation overgrowth. 14 run on precomputed fields only. 13 return MISSING until trained CV weights land. 7 are passthrough.
  • Family C weights stated in the dossier: tax delinquency 0.95, pre-foreclosure 1.0, probate 0.95.
  • Amber tier (eviction history, bankruptcy linkage, divorce-related filings): built as captures, parked, unscored, legal sign-off required. Never active scoring. This demo scores no parcel and touches none of them.
  • The 49-ingredient Recipe Engine inventory is a different 49 and stays UNVERIFIED (open item Q-SWEEP-4, upload sweep 2026-11-10). The two 49s are never merged here.

8. Gaps, stated plainly

  • Gap 1: 19 of 20 coverage cells UNSTATED. Only the Berrien90+ recipe states a territory. The FLOW_C recipes may cover several territories, but no source read names them.
  • Gap 2: St. Joseph arithmetic does not reconcile. The September 22 snapshot says 244 owner-lead rows, 162 scored, 94 explicitly non-seed. 162 plus 94 is 256, which exceeds 244. Both numbers are reported as stated; the scorer uses 162/244 for the scored share and flags the tension here.
  • Gap 3: Elkhart has no stated counts. Elkhart is a doctrine territory with a pinned adapter (FIPS 18039) and no owner-lead rows, scored count, or endpoint state in the sources read. It scores 0.00, which means unmeasured.
  • Gap 4: Davidson has scale and nothing else. 27,343 rows, the largest concentration, but no scored count, no recipe coverage, and no verification stated. It ranks first on scale alone; that is a property of the demo weights, not a finding about the county.
  • Gap 5: LaPorte endpoint not located. The 2026-11-14 pipeline run could not find a free LaPorte ArcGIS endpoint. The dossier states an SEH-hosted endpoint with 64,775 parcels pulled previously, but no URL is recorded in any workspace file. The LaPorte leg of the pull route is unverified from here.
  • Gap 6: All September 22 counts are HISTORICAL. Owner-lead rows, scored rows, and the 4 active hunt recipes are a September 22 snapshot. Only the St. Joseph endpoint counts are live (November 14). States may have changed.
  • Gap 7: The live codex text fetch does not name the Territory Engine. The Ecosystem Codex page (fetched 2026-11-14, crawled 06:46 UTC) names LandOS (Tier A, 49 signals, 148 tests, 43,897 records scored) and defines the tiers, but its 28-entry register is rendered by script and the Territory Engine row does not appear in the fetched text.   • Gap 8: No standalone territory-engine dossier exists. No standalone dossier file was found under _research. This build uses the Ecosystem Codex territory entries, the estate inventory, the IP registry, the GitHub census, and the repo itself, as the brief directed.
