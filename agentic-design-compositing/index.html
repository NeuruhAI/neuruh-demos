The Paradigm Shift: from flat generation to programmatic compositing

Flat generation is a monolithic black box. It produces an uneditable, baked-in JPEG. The specification moves to a programmatic compositing architecture built on Separation of Concerns: Generative AI is relegated to a modular asset creator rather than a final layout engine. Decoupling background imagery from typography and layout logic eliminates the structural failures of traditional GenAI, such as garbled text and the inability to manipulate individual design elements post-generation.

Figure 1 - Flat generation fuses everything into one raster. Compositing keeps every element as an independent, stateful layer, so each one stays editable after generation.

Four advantages the spec claims for the composited approach

Granular Editability

A layered state lets users programmatically modify text strings, swap logos, or adjust asset positioning inside an HTML5/CSS environment without re-generating the entire image.

Structural Integrity

A parameterized approach makes the layout follow rigid design patterns, neutralizing the "AI drift" that characterizes standard text-to-image prompts.

Typography Precision

Rendering text as a distinct vector or HTML layer solves the "text problem" entirely: crisp, correctly spelled headers and subtext.

Professional Normalization

A composited approach injects technical print and digital standards, specific DPI settings and color profiles, that are inaccessible in flat image generation.

The Core Open-Source Technology Stack

Five modular components, unified by the Davinci protocol as the standardized data exchange layer. A modular, open-source architecture prevents vendor lock-in and provides schema validation, per the blueprint.

How ComfyUI and ControlNet work together

ComfyUI is the primary engine for deterministic asset generation. Its node-based architecture lets the pipeline integrate ControlNet directly. By feeding the engine a black-and-white grid mask, the system enforces strict spatial boundaries: the AI generates textures and imagery only where intended, while specifically leaving designated negative space (empty areas) where the typography and hero assets will be programmatically injected by the downstream assembly layers.

Design rule, from the spec

The background is never asked to carry text. The background prompt in the Davinci payload ("high-end residential neighborhood, blurred background, warm sunset lighting, hyper-realistic") is paired with a negative prompt ("text, watermarks, ugly architecture, cartoonish") that explicitly forbids text in the generated asset. Text lives in its own layer, above the background, rendered by the canvas engine.

Why open-source, per the blueprint

  • No vendor lock-in: each layer is a replaceable open component, not a proprietary endpoint.
  • Schema validation: JSON payloads between agents are validated before handoff, so a bad payload fails before it reaches the canvas.
  • Deterministic assembly: the same payload renders the same layout every time, because layout is code, not sampling.

Note the tension the spec does not resolve: ComfyUI plus Stable Diffusion generation is stochastic by nature, while the assembly layer is deterministic. The spec's answer is to confine the stochastic part to the background texture and keep everything structural in code. That boundary is the whole architecture.

The "Davinci" Tokenization Protocol: Structured JSON Layering

The Davinci protocol is the architectural backbone. It translates high-level human intent into a machine-executable, tokenized instruction set. Instead of "messy" natural language prompts, a parameterized JSON payload treats every design element, from aspect ratio to font weight, as a discrete data point. Text is a non-AI-generated layer, which is what makes professional-grade legibility and brand compliance possible.

Four specialized agents, one sequential pipeline. The Davinci JSON payload is the handoff between them: each agent reads the payload, does its job, and passes a validated payload forward. Precision Compositing logic turns the workflow from a creative hallucinator into a precision engine.

Precision Compositing: the user-uploaded asset pipeline

  
User-uploaded assets are prioritized as high-priority data points. The Architect Agent assigns an upload to a layer in the JSON payload (hero_image or branding), defining the source file and agent actions such as remove_background or color_correct. The Asset Generation Agent prepares the image, triggering background removal APIs for headshots and ensuring the AI-generated background (via ComfyUI) leaves specific empty space for the uploaded property photo. The Assembly Agent pushes the processed photo into an HTML5 canvas engine as an independent layer, so the user can click, resize, or swap the photo in the browser. The background reserves empty space for the property photo because the elements are placed as independent layers rather than baked into the background, so the design remains fully interactive and structurally sound.

Layout Enforcement and Aesthetic Precision

  
Rigid structural boundaries are enforced by architectural constraints inside the generation workflow, not by prompt engineering. ControlNet inside the ComfyUI pipeline feeds a black-and-white spatial grid to the model, and the grid instructs the AI to generate negative space in designated regions, so complex background patterns never interfere with the areas reserved for typography or branding.


  

    
    
Figure 3 - The ControlNet enforcement loop. The black-and-white grid reserves negative space; the background texture is generated only where allowed; the Assembly Agent then injects typography, hero, and branding into the reserved zones. The diagram is a schematic of the spec's description, not a screenshot of a real ComfyUI run.
